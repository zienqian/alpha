01先区分三种“描述”

信息谁生成 / 何时生成目前有吗？
工具能力说明
ToolInfo.description		开发者在注册工具时写死，例如“Execute a command…”。告诉模型工具能做什么。有。它不是“这次为什么要运行命令”。
本次调用的目的
arguments.description		模型与 command 同时生成，例如“验证消息渲染与工具执行状态”。执行前就已存在。目前没有。建议为 run_command 的输入 schema 新增可选字段。
执行标题 / 结果
Ran / Failed (exit 1)		UI 根据真实命令和结果拼接。Running 在开始时出现；Ran / Failed 在结果返回后确定。目前只有工具名称与 note，需透传实际参数、退出码与结果。

02完整时序

01 / MODEL模型生成参数

command 与 description 同一次生成。Loading 显示“正在思考”。

02 / COMMIT完整调用提交

toolCalls 已确定。UI 显示命令和描述，工具为 queued。

03 / APPROVAL必要时等待确认

审批显示真实 command / cwd。状态变为静态“等待确认”。

04 / START工具开始执行

记录变 Running；底部采用 description，开始扫光。

05 / RESULT提交工具结果

更新 Ran / Failed、输出和退出码。模型继续时显示“正在整理结果”。

当前实现的关键限制：ADK 等完整模型结果返回后才提交 assistant 消息，工具参数的流式片段不直接作为执行来源。因此描述最早在 message.commit 时进入 UI。生成中不解析未完成 JSON，用通用 Loading 填补这一阶段。

01交互与布局

  • 记录平铺。每次工具调用一个稳定条目：状态 + 真实命令 / 路径；下一行是目的描述，下面缩进输出。普通说明和最终回复仍按原顺序穿插。
  • Loading 固定在输入框上方。位于 composer-dock 内，不随消息区滚动。生成、准备、执行、审批、保存各自对应真实阶段；结束后静态呈现。
  • 历史记录不动画。工具行仅更新 Running / Ran / Failed；底部状态扫光，字体、字重、行高不变。
  • 大输出有界显示。保留头尾预览与明确省略行数，不添加任务折叠按钮；规范历史保存完整工具结果。返回内容本身截断时显示 truncated / outputIncomplete，不冒充全文。
  • 保留阅读位置。沿用 ScrollBox，原来贴底才跟随；用户上翻时不拉回。底部状态改变只重绘 dock。

02底部状态由什么驱动

阶段底部文字动画 / 记录
模型生成正在思考下一步…扫光；完整调用提交前不创建命令条目。
调用提交准备执行：调用描述静态；条目先为 queued，审批前也可看见命令。
等待审批等待你确认运行命令停止扫光；真实命令和目录在审批面板显示。若同时有其他任务运行，补充运行数量。
工具运行正在 + 调用描述扫光；多工具时显示当前描述和 N 项运行中，避免过快轮播。
生成最终回复正在整理执行结果…继续扫光；上个工具记录已静态，不能提前显示整轮完成。
取消 / 停止正在停止… → 已停止请求与确认结束分开；已完成事实不变，未确认副作用保留 unknown。
保存 / 完成正在保存会话… → 已完成保存确认后停动画；失败显示真实保存错误。
工具失败但模型继续正在处理执行结果…工具记录保留失败；底部仍反映当前阶段，只有 run 结束才终止活动状态。

优先级：关闭 / 取消过程 → 待审批 → 实际工具运行 → 模型生成 / 回答 → 保存 → 终态。不能用一次 tool.end 直接把 chat.busy 设为 false。权限、审批与输入的既有语义继续生效。

03数据模型与事件适配

// 拟议应用展示模型；不增加 Provider / ADK 的通用执行协议
type ToolRecord = {
  id: string;                 // assistantId + ':' + callId
  assistantId: string;
  callId: string;
  name: string;
  description: string;
  descriptionSource: 'model' | 'fallback';
  command?: string;
  cwd?: string;
  path?: string;
  status: 'queued' | 'running' | 'awaiting_approval'
    | 'succeeded' | 'failed' | 'denied'
    | 'not_executed' | 'outcome_unknown';
  exitCode?: number;
  outputPreview?: string;      // 有界预览
  truncated?: boolean;
  outputIncomplete?: boolean;
  startedAt?: number;          // 本轮单调时钟，旧历史不伪造耗时
  finishedAt?: number;
};

// tool.queued 是拟议的应用事件，从 assistant.commit 的 toolCalls 派生。
// 实时 / 历史共享 normalizeToolRecord，不从 note 文本猜执行状态。
  1. runtime/events.ts在 assistant 提交时读取规范 messageId 与完整 toolCalls，关联正在流式显示的 modelCallId；透传命令、参数、描述，按原调用顺序插入 queued 条目。流式 UI key 保持稳定。
  2. tool.start更新条目；tool.end或 toolResult 的 message.commit按 assistantId + callId 读取规范结果。重复通知 upsert，不重复插入。
  3. runtime/history.ts从 assistant.toolCalls 恢复参数与描述，再以 toolResult 回填结果；复用归一化函数。老历史缺描述用规则兜底，缺耗时不显示。
  4. ApprovalRequest补 assistantId / callId，从 CodingAction.call 透传；denied 可能没有 start，也必须能直接进入终态。
  5. 首版从最终 toolResult 显示输出；运行时显示“等待命令返回”。如要接实时 stdout，另接 command.output；它目前只有 runId / callId，需补 assistantId 或建立无歧义映射，防止重复 callId 串线。
execution=succeeded 不足以判成功。CodingToolResult 用 {ok:false, code, detail}表示业务错误，非零退出码也走该分支，而 core execution 仍可能是 succeeded。UI 组合规范 execution 与已知工具结果判断；未知工具不强套 JSON 规则，结果未知不能标绿。

04扫光与性能

参考 Codex 当前状态摘要：首次等 600ms，扫过 1 秒，每 4 秒一个周期。浅色背景扫过处更深，只有亮度变化；状态词只随真实事件变化。

HTML 预览正式 OpenTUI 实现
CSS gradient + background-clip:text。用已安装 0.8.1 的 StyledText / TextChunk.fg 着色；终端没有 CSS。
减少动态时静态，页面隐藏时暂停。按 grapheme 切分、按终端列宽计算波峰，中文和 emoji 不按 UTF-16 下标切。
只给输入区状态标签加动画。ShimmerText 的局部时钟：扫过期间 20–30fps，静止间隔只调度下次唤醒；卸载 / 终态 / reduced motion 清理。
真实状态变化进入 aria-live，秒表不播报。文字语义变更才重置延迟；秒数 / 计数更新不重置相位。低色彩环境退化为静态。
