ALPHA / PROVIDER COOKBOOK

Provider，
从配置到调用。

基于当前代码整理：如何配置服务和模型、发起请求、处理工具调用，以及接入自定义适配器。

所有 URL 和模型 ID 均为占位符。示例展示现有 API，不代表已通过真实厂商验证。不同代码块独立说明；明确标注“接上例”的代码使用前一段变量。
01 /

快速开始

一个完整配置可以管理多个 Provider，每个服务包含自己的模型别名。获取模型时不发送网络请求，generate() 才发起请求。

provider.config.ts
import { createProvider, defineProviderConfig } from '@alpha/provider';

export const config = defineProviderConfig({
  providers: {
    openai: {
      adapter: 'openai-responses',
      options: { apiKey: { env: 'OPENAI_API_KEY' } },
      models: { chat: { id: 'your-openai-model-id' } },
    },
    anthropic: {
      adapter: 'anthropic-messages',
      options: {
        apiKey: { env: 'ANTHROPIC_API_KEY' },
        maxOutputTokens: 1024,
      },
      models: { chat: { id: 'your-anthropic-model-id' } },
    },
    thirdParty: {
      adapter: 'openai-completions',
      options: {
        baseURL: 'https://api.example.com/v1',
        apiKey: { env: 'THIRD_PARTY_API_KEY' },
      },
      models: {
        chat: { id: 'your-chat-model-id' },
        reasoning: { id: 'your-reasoning-model-id' },
      },
    },
  },
});

export const provider = createProvider(config);
app.ts · 接上面的配置
import { provider } from './provider.config.js';

const model = provider.use('thirdParty', 'chat');
const result = await model.generate({
  messages: [
    { role: 'system', content: '你是一个简洁的助手。' },
    { role: 'user', content: '解释什么是 monorepo。' },
  ],
  maxOutputTokens: 512,
  temperature: 0.3,
});

console.log(result.text);
console.log(result.usage); // 可能为 undefined，取决于服务响应
在 PowerShell 中可为当前终端设置密钥：$env:THIRD_PARTY_API_KEY = '你的密钥'。实际运行时须替换地址、模型 ID 并配置有效凭证；不要把密钥提交到仓库。
02 /

四种内置适配器

Codex 示例使用官方 Sign in with ChatGPT 授权得到的 access token 调用公开 Responses API；应用负责登录和刷新，不直接实现内部 Codex backend。以下对象可分别放在 config.providers 下，models 的键是自定义别名，id 是服务端真实模型名称。

Provider 配置项
// Responses 协议
openai: {
  adapter: 'openai-responses',
  options: { apiKey: { env: 'OPENAI_API_KEY' } },
  models: { chat: { id: 'your-model-id' } },
},

// Completions 协议：OpenAI 或兼容服务
openaiCompletions: {
  adapter: 'openai-completions',
  options: {
    apiKey: { env: 'OPENAI_API_KEY' },
    baseURL: 'https://api.example.com/v1', // 可选覆盖
  },
  models: { chat: { id: 'your-model-id' } },
},

// Codex 授权的 Responses：token 由应用自行获取和刷新
codex: {
  adapter: 'openai-codex-responses',
  options: { accessToken: { env: 'CODEX_ACCESS_TOKEN' } },
  models: { main: { id: 'your-authorized-model-id' } },
},

// Anthropic Messages：maxOutputTokens 可放在配置或 generate() 中
anthropic: {
  adapter: 'anthropic-messages',
  options: {
    apiKey: { env: 'ANTHROPIC_API_KEY' },
    maxOutputTokens: 1024,
  },
  models: { chat: { id: 'your-model-id' } },
},

// 第三方兼容端点：使用 Completions 协议
thirdParty: {
  adapter: 'openai-completions',
  options: {
    baseURL: 'https://api.example.com/v1',
    apiKey: { env: 'THIRD_PARTY_API_KEY' },
    headers: { 'x-client-name': 'alpha', 'x-gateway-key': { env: 'GATEWAY_KEY' } },
    queryParams: { 'api-version': 'example-version' }, // 可选
  },
  models: { chat: { id: 'your-model-id' } },
},

// 本地服务没有认证时，必须显式声明
local: {
  adapter: 'openai-completions',
  options: {
    baseURL: 'http://127.0.0.1:11434/v1',
    apiKey: { none: true },
  },
  models: { chat: { id: 'your-local-model-id' } },
},
连接参数必须与目标服务实际接口匹配。baseURL 不接受内嵌凭证、查询参数或 fragment；headers 中的敏感值使用环境变量引用；queryParams 不存放密钥。不同服务的工具调用能力需要独立验证。

文本、多轮与模型列表

消息由调用方传入；Provider 不保存对话历史，也不自动切换模型。

text.ts · 使用第 01 节的 provider
import { provider } from './provider.config.js';
import type { Message } from '@alpha/provider';

console.log(provider.list()); // provider 名称、adapter、模型别名和配置的元数据

const model = provider.use('thirdParty', 'chat');
const history: Message[] = [
  { role: 'system', content: '回答简洁。' },
  { role: 'user', content: '我叫小明。' },
  { role: 'assistant', content: '你好，小明。' },
  { role: 'user', content: '我叫什么？' },
];

const result = await model.generate({ messages: history });
console.log(result.outcome, result.text, result.finishReason, result.usage);

// 切换模型需要显式选择另一条配置
const reasoning = provider.use('thirdParty', 'reasoning');
STREAM /

流式输出

立即接收文本增量，生成完成后再检查状态和工具调用。

stream.ts
const controller = new AbortController();
try {
  for await (const event of model.stream({
    messages: [{ role: 'user', content: '你好' }],
    signal: controller.signal,
  })) {
    if (event.type === 'text-delta') process.stdout.write(event.text);
    if (event.type === 'tool-call') console.log(event.toolCall);
    if (event.type === 'finish') console.log(event.result.outcome);
  }
} catch (error) {
  console.error(error); // 取消或服务错误
}
文本增量可能来自随后被截断或拒答的结果，最终状态以 finish 为准。工具调用已包含在 finish.result.toolCalls 中，避免重复执行。中途 break 会释放响应体；需要主动取消时调用 controller.abort()。
MODEL /

配置模型元数据

在 Provider 的模型条目中设置描述信息；连接地址、协议和认证仍由 Provider 配置一次。

模型配置 · 放在 providers.ollama.models 中
reasoning: {
  id: 'gpt-oss:20b',
  name: 'GPT-OSS 20B (Ollama)',
  reasoning: true,
  input: ['text'],
  cost: { input: 0, output: 0, cacheRead: 0, cacheWrite: 0 },
  contextWindow: 131072,
  maxTokens: 32000,
  thinkingLevelMap: {
    minimal: null, low: null, medium: null, high: 'high', xhigh: null,
  },
  compat: { supportsDeveloperRole: false, supportsReasoningEffort: false },
}
读取信息 · 假设已配置 ollama
const model = provider.use('ollama', 'reasoning');
console.log(model.modelId);           // gpt-oss:20b
console.log(model.metadata?.name);    // GPT-OSS 20B (Ollama)
console.log(model.metadata?.compat);  // 已配置的兼容性信息
console.log(provider.list());         // 各模型及其配置元数据
显式启用思考等级 · 模型需支持该参数
// 前面的示例将 supportsReasoningEffort 设为 false，不能传 thinkingLevel。
// 对支持 reasoning effort 的模型，可将其设为 true 并提供映射：
// compat: { supportsReasoningEffort: true },
// thinkingLevelMap: { low: null, medium: 'medium', high: 'high' },
const result = await model.generate({
  messages: [{ role: 'user', content: '分析问题' }],
  maxOutputTokens: 2048,
  thinkingLevel: 'high',
});
maxTokens 限制请求的输出 token；thinkingLevelMap、reasoning 和 compat 参与请求校验和协议转换。contextWindow、input 和 cost 仍只用于描述，不自动开启多模态或计算费用。cost 约定为美元 / 百万 token；未知价格应省略，而不是填 0。示例数值来自示意，实际信息由使用者核实。
04 /

工具调用：你负责执行

模型可以请求调用工具；Provider 负责协议转换，应用负责校验参数、执行工具并传回结果。这里演示一轮，后续再次返回工具调用时需继续处理或设置上限。

tools.ts · 使用第 01 节的 provider
import { provider } from './provider.config.js';
import type { Message, ToolDefinition } from '@alpha/provider';

const model = provider.use('thirdParty', 'chat');
const tools: ToolDefinition[] = [{
  name: 'get_weather',
  description: '查询城市天气',
  inputSchema: {
    type: 'object',
    properties: { city: { type: 'string' } },
    required: ['city'],
    additionalProperties: false,
  },
}];
const messages: Message[] = [{ role: 'user', content: '北京天气如何？' }];
const first = await model.generate({ messages, tools });

if (first.outcome === 'tool_calls') {
  messages.push({ role: 'assistant', content: first.text, toolCalls: first.toolCalls, continuation: first.continuation });
  for (const call of first.toolCalls) {
    // 工具参数来自模型，执行前必须按应用规则校验。
    if (call.name !== 'get_weather' || typeof call.arguments.city !== 'string') {
      throw new Error('不支持的工具或参数');
    }
    const weather = `${call.arguments.city}：晴，22°C`; // 示例数据
    messages.push({ role: 'tool', toolCallId: call.id, content: weather });
  }
  const next = await model.generate({ messages, tools });
  console.log(next.outcome, next.text);
  // next.toolCalls 非空表示还需要继续执行工具；此例只演示一轮。
} else {
  console.log(first.outcome, first.refusal ?? first.text, first.incompleteReason);
}
实际服务可能拒绝某些工具 schema 或不支持工具调用。模型参数的校验、工具权限、副作用控制和多轮上限由应用或未来 ADK 负责。
CONTEXT /

推理模型的工具调用续接

Responses 使用保存的响应 ID；Anthropic 使用原样保留的 thinking 和签名。

Responses：传入新增的工具结果
const first = await model.generate({ messages, tools });
if (first.outcome === 'tool_calls' && first.responseId) {
  const toolMessages = await runTools(first.toolCalls); // 应用负责校验和执行
  const next = await model.generate({
    previousResponseId: first.responseId,
    messages: toolMessages,
    tools,
  });
}
Anthropic：保留 assistant 协议数据
messages.push({
  role: 'assistant', content: first.text, toolCalls: first.toolCalls,
  continuation: first.continuation,
});
messages.push({ role: 'tool', toolCallId: first.toolCalls[0].id, content: '工具结果' });
const next = await model.generate({ messages, tools });
Responses 续接依赖服务保存先前响应，系统指令需按需再次传入。Anthropic continuation 可能含敏感原始内容，请原样保存且不要跨模型使用。Completions 可通过 options.maxTokensField 选择 max_tokens 或 max_completion_tokens。
05 /

请求参数与返回值

字段作用说明
messages消息数组，必填且非空角色支持 system、developer、user、assistant、tool；developer 是否支持取决于协议及模型配置。content 为字符串。
tools工具定义，可选包含 name、可选 description 和 JSON inputSchema；Provider 不执行工具。
maxOutputTokens输出 token 上限，可选必须是正整数，不能超过模型 maxTokens；Anthropic 需要在配置或请求中提供，请求优先。
thinkingLevel思考等级，可选通过模型 thinkingLevelMap 映射至对应协议字段；不支持的等级在请求前报错。
temperature采样参数，可选要求有限数字；允许范围由目标服务决定。
signalAbortSignal，可选传递给 fetch，支持取消。
result.outcome统一结果状态completed、tool_calls、refused、incomplete 或 unknown；只有 tool_calls 可以执行工具。
result.refusal / incompleteReason拒答内容或未完成原因服务提供信息时返回；未完成时 text 可能包含部分输出。
result.text文本内容工具调用时可能为空字符串。
result.toolCalls工具调用数组每项包含 id、name 和 JSON 对象 arguments；没有调用时为空数组。
result.finishReason完成原因原始服务返回的字符串或 null；不同协议的值不同。
result.usage输入和输出 token可为 undefined；各 token 字段也可能缺失。

HTTP /

注入 HTTP 请求头

在 Provider 连接中设置默认 headers；单次 generate 可以提供额外 headers，且覆盖同名配置（名称不区分大小写）。

provider.config.ts · Provider 条目示例
gateway: {
  adapter: 'openai-completions',
  options: {
    baseURL: 'https://gateway.example.com/v1',
    apiKey: { env: 'MODEL_API_KEY' },
    headers: {
      'x-client-name': 'alpha',
      'x-gateway-key': { env: 'GATEWAY_KEY' },
    },
  },
  models: { chat: { id: 'your-model-id' } },
}
request.ts · 假设已配置 gateway
const model = provider.use('gateway', 'chat');
const result = await model.generate({
  messages: [{ role: 'user', content: '你好' }],
  headers: {
    'x-request-id': 'request-123',
    'X-Client-Name': 'alpha-override', // 仅覆盖本次请求
  },
});
认证及协议头由内置适配器管理：authorization、proxy-authorization、cookie、set-cookie、anthropic-version、content-type 不能通过自定义 headers 覆盖；Anthropic 还保留 x-api-key。Completions / Responses 可以设置 x-api-key 或 api-key。环境变量在 use 时读取，轮换后重新 use；请求级 headers 每次直接传字符串。自定义 adapter 需自行实现 header 行为。
06 /

密钥轮换与取消

createProvider() 不读取密钥；每次 use() 读取当前环境变量并创建新模型。之前创建的模型继续使用当时的密钥。

lifecycle.ts · 使用第 01 节的 provider
import { provider } from './provider.config.js';

const previous = provider.use('thirdParty', 'chat');
process.env.THIRD_PARTY_API_KEY = '新的服务端密钥';
const current = provider.use('thirdParty', 'chat');
// previous 仍持有旧凭证；current 使用新凭证。

const controller = new AbortController();
const timer = setTimeout(() => controller.abort(), 10_000);
try {
  const result = await current.generate({
    messages: [{ role: 'user', content: '你好' }],
    signal: controller.signal,
  });
  console.log(result.text);
} finally {
  clearTimeout(timer);
}
上例仅演示进程内环境变量变化。真实部署应由服务端密钥管理和进程生命周期决定如何轮换；取消错误会透传 AbortSignal.reason。
07 /

错误处理

errors.ts · 使用第 01 节的 provider
import { ProviderError } from '@alpha/provider';
import { provider } from './provider.config.js';

try {
  const model = provider.use('thirdParty', 'chat');
  const result = await model.generate({ messages: [{ role: 'user', content: '你好' }] });
  console.log(result.text);
} catch (error) {
  if (error instanceof ProviderError) {
    console.error(error.code, error.path, error.status);
    // 可按 code 分支；HTTP 状态码仅在可用时存在。
  } else {
    throw error; // 例如 AbortSignal 的取消原因
  }
}
code发生阶段示例
CONFIG_INVALIDcreateProvider配置结构、连接参数或自定义 adapter 配置无效。
ADAPTER_NOT_FOUNDcreateProvider指定的自定义 adapter 未注册。
PROVIDER_NOT_FOUND / MODEL_NOT_FOUNDuse传入不存在的 Provider 或模型别名；动态输入在运行时检查。
SECRET_MISSING / ADAPTER_INIT_FAILEDuse密钥不存在，或自定义 adapter 无法创建模型。
INVALID_INPUT / REQUEST_FAILED / RESPONSE_FAILED / INVALID_RESPONSEgenerate请求参数无效、HTTP 请求失败、服务报告生成失败，或响应格式无效。

HTTP 错误不会包含响应正文。运行时错误可能没有 path 或 status，不要把上游请求内容和密钥记录到日志。

实现自定义适配器

自定义适配器提供 validate 和 createModel，返回 Alpha 自己的 LanguageModel。下面是无需网络的完整演示，不代表真实服务。

custom.ts · 可独立阅读
import { createProvider, defineProviderConfig } from '@alpha/provider';
import type { ProviderAdapter } from '@alpha/provider';

const echoAdapter: ProviderAdapter = {
  validate(options) {
    if (typeof options.prefix !== 'string') throw new Error('prefix is required');
  },
  createModel(options, modelId) {
    const prefix = String(options.prefix);
    return {
      provider: 'echo',
      modelId,
      async *stream(input) {
        yield { type: 'finish', result: await this.generate(input) };
      },
      async generate(input) {
        const last = input.messages.at(-1);
        return {
          outcome: 'completed',
          text: `${prefix}: ${last?.content ?? ''}`,
          toolCalls: [],
          finishReason: 'stop',
        };
      },
    };
  },
};

const config = defineProviderConfig({ providers: {
  demo: {
    adapter: 'echo',
    options: { prefix: '收到' },
    models: { chat: { id: 'echo-v1' } },
  },
} });
const provider = createProvider(config, { adapters: { echo: echoAdapter } });
const model = provider.use('demo', 'chat');
const result = await model.generate({ messages: [{ role: 'user', content: '你好' }] });
console.log(result.text); // 收到: 你好
真实适配器可使用第三个参数 context.getEnv 和 context.fetch。它负责自行处理认证、协议、错误与能力；验证及模型创建是同步的，内置 adapter 不允许覆盖。

当前实现的边界

已支持

静态配置、多 Provider 与模型、四种内置适配器、流式与非流式文本、工具调用数据映射、取消和自定义适配器。

还没有

多模态、自动执行工具、Agent 循环、自动重试或 fallback、异步密钥解析。

验证状态

已使用模拟 HTTP 测试流式、协议与工具往返；尚未使用真实厂商凭证做端到端验证。

运行前先在仓库根目录执行 pnpm install --frozen-lockfile 和 pnpm build。包目前是 workspace 内部私有包；示例应放在声明了 @alpha/provider workspace 依赖的应用中。
