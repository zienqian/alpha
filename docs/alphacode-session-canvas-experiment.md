# AlphaCode 实验性多会话画布

> 当前实现：v2 停靠工作区，2026-11-14。以下 v2 记录优先；文末保留的 v1 网格方案是历史设计，不能作为当前行为或性能承诺。

## v2 交互与实现

采用 `flexlayout-react@0.11.1`，移除 React Grid Layout。整个右侧主内容区都是画布，移除原来的全局会话标题和独立“画布”工具栏。左侧会话整行直接可拖，原来的小拖拽手柄已移除；菜单中的“添加到画布”保留为键盘替代入口。

- 拖动会话、标签或标签栏空白处的当前会话，只有落到标题栏才合并为标签组，并按位置插入标签；标题栏命中优先于全局边缘停靠。正文区域按归一化距离选择最近的可用方向，预览并执行上下或左右分屏，中部不再合并；目标不可见或唯一标签拖回自身正文时不提交操作。空间不足时扩展画布并在内部滚动；空画布允许直接放入首个会话。所有窗口宽度均保留标题合并与正文分屏。共享分隔缝全长可拖，实时改变相邻区域比例。
- 标签组右上角只提供放大/还原与折叠，移除三点菜单及其分栏、合并、重置和关闭入口。标签自身的悬停关闭保留。左右分栏折叠为 44px 竖向标题条，上下分栏或单独区块折叠为约 42px 横向标题栏；点击标题或从侧栏选择会话会展开并恢复原比例。折叠时卸载正文和额外订阅，草稿由共享工作区保留；全部折叠仍保留标题，不触发新建会话。折叠状态随布局保存，标题栏不提供会话摘要入口。
- 首次打开当前会话，第二个会话默认并排，后续默认加入活动组；区块数和会话数均不设置上限。已打开会话通过菜单再次添加时仅聚焦；直接拖动其侧栏行时，指针手势在松手后提交移动原 TabNode 的 action，保留面板 ID，可继续合并或停靠到边缘。
- 缩小窗口不会自动收起左侧导航，也不会将画布替换成单面板切换栏。低于 768px 时侧栏宽度为 clamp(160px, 32vw, 264px)，仍可手动折叠。右侧保留原分栏结构、会话视图和拖拽处理器；低于布局最低尺寸时在画布内部滚动。展开面板至少 220px × 220px（含标题栏），扩大窗口继续使用原比例；窗口尺寸变化不保存布局、不重建草稿与连接。
- 关闭面板不删除会话、不取消服务端任务。关闭最后一个标签后自动打开原有的新会话输入界面，仅复用空白本地草稿，保留未发送内容，不再显示画布占位说明或“添加当前会话”按钮。实验开关仍默认关闭，关闭后恢复普通会话页。

`SessionWorkspaceProvider` 继续持有草稿、创建流程和命令实例。各个 `SessionPane` 按 session ID 绑定数据与操作，详情流由引用计数共享；全局索引仅订阅一次。未选中或最大化后隐藏的标签释放会话视图及其订阅，草稿和待确认命令保留。根工作区继续保留当前选中会话的一条详情流。

FlexLayout 和相关样式只由 lazy 画布模块导入。标签和侧栏拖动改用 Pointer Events：移动超过 5px 才启动，指针捕获保证移出标签后仍能跟随；启动时立即设置首个浮层与落点位置，后续指针移动经 requestAnimationFrame 合并，只更新轻量 DOM 浮层与落点预览；松手才提交一次布局 action。整块画布的空白与分隔缝归入最近区域，最外侧 18px 支持全局停靠；分屏不因现有区域过小而拒绝；新增区块后画布按布局最低尺寸扩展。Esc、pointercancel、失焦或组件卸载会清理手势；Esc 后的松手不会误点原会话。侧栏触屏保留纵向滚动，触屏添加使用菜单；画布标题栏允许指针拖动。

实时缩放的 adjusting action 不触发画布父级更新或 localStorage 写入；最终 action 才提交比例。折叠栏旁的分隔缝支持向外拖动展开并调整大小：超过 5px 后展开，后续移动按 RAF 合并；松手只保存一次，Esc、pointercancel、失焦或卸载恢复折叠状态和原比例。正文订阅仅在展开/取消的组合 action 时更新，逐帧调整权重不重算会话。会话内容采用稳定 ID 和 memo 边界，避免几何变化重建历史消息。缩放仍涉及浏览器重排，多会话并行仍有额外开销。

折叠标题条使用主题正文底色（浅色模式为白色），选中项仅加深文字；标题之间为居中的 16px 短分隔线，竖栏为横线，横栏为竖线。只有悬停标题时显示内缩圆角灰底，键盘聚焦保留轮廓。点击标题仍恢复折叠前比例，拖动分隔缝则使用本次拖动的新尺寸。

视觉延续现有紧凑工作台：画布映射应用浅深主题的语义颜色，正文保持实色，标签使用继承的系统字体和 14px 字号，操作复用共享按钮与菜单。标签按用户提供的 LeetCode 截图改为浅灰标题栏、扁平文字标签、蓝色图标及标签间细竖线；不再使用胶囊底座、选中项阴影或下划线，桌面与窄屏共享样式。标签栏高度 40px、分隔缝 8px 保持紧凑；面板使用应用的 xl 圆角（14px），独立渲染的正文层同步裁切底部内圆角（13px），修复正文覆盖圆角的问题。输入框复用应用的 2xl 圆角（18px），操作按钮使用 md 圆角（8px）、28px 点击区域；全部操作图标复用全站 16px 外框；折叠箭头由共享样式缩放内部路径并补偿线宽，使可见主轴与放大/还原均为 12px、实际线宽均约 1.33px，放大/还原、关闭和溢出图标不再混用布局库默认资源。强调蓝使用 primary 主题色，浅深主题自动适配。标签紧邻排列，关闭按钮在鼠标悬停或键盘聚焦时替换左侧图标，标题与分隔线不跳动；无悬停能力的触屏保留可见的独立关闭入口。拖动时显示小型标题浮层、1px 蓝色边框与 10% 蓝色落点底色、四边蓝色停靠提示；标题合并只以 2px × 20px 蓝色插入线标记标签前、标签间或末尾的位置，同一面板内移动也更新插入线，隐藏整块预览及画布边缘提示；正文分屏预览对应半区，不显示插入线；落点切换为 110ms，减少动态效果偏好下取消过渡。分隔缝平时只显示 24px 小握柄，整条缝仍可拖；输入框底栏保持单行，权限标签按可用宽度省略。

存储使用 `alphacode-session-canvas-v2`：仅保存已创建会话引用、分栏树、比例、标签顺序、选中项和折叠标记。清洗重复 ID、非法比例和任意库配置，完整保留有效区块、标签和嵌套结构，不保存标题正文、消息、附件或草稿。读取旧 v1 布局时迁移会话引用及焦点，按新分栏模型重新排列，不保留网格坐标。

## 历史：v1 网格方案与验证记录

> 状态：首版实验原型已实现，完整性能矩阵待验收。日期：2026-11-14。范围：AlphaCode Web，以及复用 Web 界面的桌面端。

## 原型交付记录

已接入 `react-grid-layout@2.3.0`。在「设置 → 实验性功能 → 多会话画布」开启，默认关闭。支持侧栏手柄拖入或点击添加、最多 4 个独立会话、标题拖动、右下角缩放、键盘调整、重置、布局保存、窄屏单面板及关闭实验后恢复普通会话。面板关闭不删除会话或取消服务端任务。

共同的 `SessionWorkspaceProvider` 保存草稿、创建流程和 `SessionCommands`；`useSessionWorkspace(sessionId)` 给面板绑定独立目标。详情流由 `SessionStreams` 引用计数共享，索引订阅仅由外层工作区持有。画布和样式经动态 import 加载，关闭时不挂载网格；拖动过程只改变几何，落下时保存一次。普通工作区保留当前会话的一条详情流，包括设置页和画布全部关闭后的状态。

验证记录：

- 最终回归：30 个测试文件、187 项测试通过（`--maxWorkers=2`）；两份 TypeScript 配置、生产构建及国际化校验通过。ESLint 无新增警告，保留 10 条既有警告。导航回归测试显式等待前进按钮可用，避免页面渲染与历史状态 effect 之间的测试竞态。
- 集成测试覆盖独立草稿与发送、共享连接、关闭释放额外连接、本地首次发送后稳定 panelId、复用草稿不串会话、不确定发送结果跨模式保留重试 ID、窄屏、损坏布局、面板上限，以及拖动期间不重建消息历史、不逐帧写存储。
- 真实浏览器验证了侧栏拖入、标题拖动、缩放、键盘调整、1440px 桌面及 390px 窄屏展示。
- 生产构建主入口从约 **323.12 kB gzip** 增至 **326.98 kB gzip**，增加约 **3.86 kB（3.77 KiB）**。画布异步 JS 为 **24.62 kB gzip**，异步 CSS 为 **1.00 kB gzip**。主样式增加约 **0.21 kB gzip**。这些是构建大小，不代表运行时性能数据；同步 JS 尚高于原先建议的 3 KiB 目标。

仍需验证／完善：4 条各约 500 消息的长历史并行输出、生产包输入延迟和拖拽帧率、20 次开关循环的内存、桌面 WebView 专项性能。跨展示模式的阅读滚动位置尚不保留；草稿和待确认命令状态保留。布局暂按应用 origin 保存在本机，同一 origin 切换数据库时没有独立布局命名空间。本地未发送面板不写持久布局，草稿仍可从侧栏找回。以下保留基础设计与正式验收目标，不能将待验收项视为已实现保证。

增加一个默认关闭的「多会话画布」实验开关。用户在设置中主动开启后，可以把多个 session 放到主内容区，拖动位置、调整大小，同时查看和操作不同会话。关闭后回到单会话界面，保留会话、草稿和已保存的布局。

首版按**应用内、网格吸附、最多 4 个面板**设计。性能目标分为两部分：关闭时不加载画布依赖、不增加订阅或布局计算；开启时控制多会话的额外开销，避免拖拽触发聊天内容重算。多会话同时渲染和接收数据必然增加资源消耗，是否达到要求以性能验收为准。

## 2 关键交互

### 开启与关闭

开启设置后，回到会话页时才加载画布。如果已有保存布局则恢复，并保证当前会话可达；当前会话不在布局且已有 4 个面板时，用当前会话替换上次聚焦面板的展示目标，原会话草稿仍保留。首次开启使用当前会话创建第一个面板，包括尚未发送的本地草稿。

关闭开关立即切换展示模式，下次返回会话页显示最后聚焦的会话。关闭操作不发送取消、删除或重试命令，不中断服务端任务；草稿、附件对象和待确认发送状态由共同的工作区状态持有，不能随着画布卸载而丢失。关闭开关不清除布局；「重置布局」恢复默认排布，不删除会话或草稿。

设置页保留在画布之外。进入设置或技能页时释放画布的额外详情订阅，按现有行为保留当前会话，返回时从缓存和服务端快照恢复其他面板。

### 添加与聚焦

侧栏普通点击继续表示「切换当前会话」：已在画布内则聚焦；尚未打开则替换聚焦面板的会话。只有「添加到画布」或拖入才新增面板，避免普通浏览不断增加连接。相同 session 在一个画布中只出现一次，重复添加时聚焦已有面板。

标题栏是面板内唯一拖动区域。输入框、消息选区、链接、代码复制、审批按钮和滚动条不触发拖动。缩放设置最小尺寸；初始建议最小宽度 360px、最小高度 320px，由原型验证输入框及审批区域是否完整可用。

每个面板可独立输入。点击或通过键盘进入面板时更新聚焦状态；发送、取消、审批、权限修改及队列编辑始终使用该面板绑定的 session ID，不能在执行时读取一个可能已经改变的全局选中 ID。全局快捷键只作用于聚焦面板。

当前 `?session=` 链接继续代表聚焦会话，不把完整布局写入 URL。显式侧栏导航保留前进后退语义；仅面板焦点变化使用 replace，避免制造大量历史记录。拖动和缩放不改变路由。

### 关闭面板与窄屏

关闭面板仅移除展示及相应详情订阅；会话仍在侧栏，运行中的任务继续执行。关闭聚焦面板后聚焦下一个面板；全部关闭后显示「添加会话」入口。面板内的新建会话沿用原有项目选择流程，并替换当前面板目标。

可用主内容区宽度小于 900px 时，先采用单面板展示并提供已打开会话切换入口，停止挂载其他聊天视图及其额外详情订阅。900px 是首轮原型阈值，按容器宽度判断，侧栏展开也纳入测量。恢复宽屏后恢复桌面布局；窄屏展示不能覆盖桌面保存坐标。

键盘用户可通过菜单添加和关闭面板，并使用「移动面板」「调整大小」操作：方向键按网格调整，Enter 提交、Escape 撤销，播报结果；拖拽不能成为唯一操作方式。各面板使用唯一的标题和内容 ID，主内容区保留统一的跳转入口。

## 4 技术结构

采用 React Grid Layout 的 v2 API；实施时验证 React 19 和桌面 WebView 兼容性后锁定具体版本及 bun.lock。官方 v2 提供 TypeScript 类型、容器测量 hook 和可配置的布局压缩策略。[v2 文档](https://github.com/react-grid-layout/react-grid-layout#whats-new-in-v2)

```text
WorkspaceLayout
├─ 共同状态：目录、草稿、创建流程、SessionCommands、聚焦会话
├─ 单会话展示：SessionPane
└─ 实验展示：lazy SessionCanvas
   ├─ 布局状态：panelId、sessionId、位置、大小
   ├─ SessionPane A → A 的详情和操作状态
   └─ SessionPane B → B 的详情和操作状态
```

### 共同状态与面板状态

将 useSessionWorkspace 拆成公共工作区状态和 `useSessionPane(sessionId)`，原有单会话展示也通过同一面板接口获取数据。保留已有 API、QueryClient、SessionGateway 和服务端协议，避免维护两套发送与审批逻辑。

SessionCommands 在工作区生命周期内只创建一次，各面板按自己的 ID 订阅命令状态并提交快照观察。草稿、创建中的请求、未确定结果的发送状态和滚动恢复信息也放在跨模式存活的状态中。各面板使用按 ID 选择的稳定快照，输入 A 的草稿不能广播整个工作区对象给 B。

详情订阅由按 session ID 管理的单一运行实例持有，按当前展示集合增删。普通模式只有当前会话，画布模式最多 4 个，设置或窄屏模式只保留当前会话。外层工具栏和侧栏读取共享快照，不另调 useSessionQuery 创建重复流。切换模式时复用仍需要的实例；关闭后释放多余实例的 AbortController、重连计时器和监听器。

新增 `SessionPane` 组合现有消息、输入框、审批和队列，支持紧凑内边距。panelId 用作稳定 React key，避免移动或重排导致重挂载。本地草稿发送后生成真实 session ID 时，保持 panelId 不变，原子迁移草稿和面板绑定；异步完成不能把焦点从用户已切换到的面板抢回来。

### 布局模块

新增 `features/session-canvas/`，放置画布组件、面板外壳、布局状态、持久化和 RGL 适配。通用会话模块不导入该目录的运行时代码。

初始采用 24 列、16px 行高、8px 间距。使用 `useContainerWidth` 测量实际主内容容器；有有效宽度后再挂载网格。选择不压缩布局并阻止碰撞，拖到其他面板上时保留最后合法位置，不推动其他面板。官方的 `noCompactor` 和 Compactor 碰撞配置支持这一策略，具体参数以锁定版本的类型为准。[布局策略](https://github.com/react-grid-layout/react-grid-layout#compactor)

标题栏绑定拖拽手柄，外部拖入使用预览占位，落下后才创建面板和详情订阅。新面板 ID 必须来自当前会话目录；布局层不接收消息正文、输入草稿或整个 workspace 对象。

位置变化保持在网格内部或画布局部状态。只在拖动结束、缩放结束、增删面板、键盘提交和重置时提交布局并保存；onLayoutChange 不能直接成为每帧写 localStorage 的入口。

## 5 实验开关与存储

设置键建议为 `experimental.sessionCanvas`，默认 false。轻量偏好 Provider 放在两种展示模式的共同父级，仿照现有主题和语言偏好处理 localStorage 不可用的情况。缺失、格式错误或不支持的配置按关闭处理；存储失败时本次会话仍可切换，并提示刷新后可能无法保留。

画布通过 React.lazy 动态导入。RGL、相关拖拽和缩放依赖及样式仅从画布模块导入，不在全局入口、设置页或公共 barrel 文件中静态导入或主动预加载。样式限制到画布类名，避免启用过一次后影响普通界面。

布局与开关分开保存，按稳定的服务端和工作区范围隔离；不能用服务端每次重启都会变化的 instanceId 作持久命名空间。首版仅一套桌面布局，避免自动断点推导覆盖用户摆放。

持久化结构建议：

```ts
type PersistedSessionCanvas = {
  version: 1;
  panels: Array<{ panelId: string; sessionId: string }>;
  layout: Array<{ i: string; x: number; y: number; w: number; h: number }>;
  focusedPanelId?: string;
};
```

其中 `i` 对应 panelId，只保存服务端已存在的会话引用和几何信息，不保存消息、审批内容、附件或草稿。本地未发送会话只保存在当前工作区内存中，刷新恢复沿用现有产品规则；本功能不额外承诺草稿跨重启保存。

读取时校验版本、数量、唯一 ID、有限整数坐标、尺寸和边界；重复或损坏项丢弃并回退到可用布局。确认删除或详情返回 404 的会话移除对应面板；暂时断网或索引获取失败不能当成会话删除。保存失败不阻塞聊天，提供可见反馈和重置入口。

## 6 性能设计与验收

### 关闭状态

冷启动且开关关闭时，RGL 的 JS 和 CSS 不应被请求或进入初始同步依赖图；没有画布 DOM、画布 ResizeObserver、拖拽监听器或额外详情订阅。开关读取和必要的公共重构仍有微小成本，因此使用构建产物及运行数据验收，不能把条件渲染等同于零成本。

曾开启后再关闭时，已加载的 JavaScript 模块不会从浏览器模块缓存中卸载；验收重点是释放运行实例、DOM、观察器和额外连接，且没有画布持续工作。共享 Query 缓存沿用既有 GC 策略，不为追求内存瞬间下降清空会话数据。

### 开启状态

布局外壳和聊天子树建立独立渲染边界。稳定 panelId、memo、引用稳定的 children 和按 session 选择的状态共同避免拖动带来消息重算；官方也明确建议缓存网格 children。[性能文档](https://github.com/react-grid-layout/react-grid-layout#performance)

纯移动主要改变外壳 transform；缩放会引起正文换行和浏览器布局，不能承诺零重排。缩放期间限制额外测量和滚动修正的频率，结束后恢复阅读锚点，只有原本跟随底部的面板继续自动滚动。A 的 token 更新不得让 B、C、D 重建消息列表。

最多同时维护 4 条详情流，加现有 1 条索引流；面板不各自订阅项目或会话索引。验证当前 HTTP 连接方式下请求是否排队，避免多条长连接挤占发送、审批和普通查询。数据快照、命令确认和审批状态保持及时；如需合并高频更新，只处理展示刷新，不丢弃业务状态。

长历史先复用现有滚动组件与内容可见性优化。若 4 面板的长历史场景未通过预算，先补消息渲染隔离或列表虚拟化，再交付对应能力；不能只用空面板证明性能。

以下为**建议的首轮验收预算，不是已测结果**：

| 场景 | 验收标准 |
| --- | --- |
| 关闭后的冷启动 | 初始请求中画布依赖为 0；新增同步 JS 目标不超过 3 KiB gzip；订阅数与改造前相同 |
| 普通模式回归 | 在相同生产构建环境和数据集下，启动、输入响应和切换会话耗时相对基线退化不超过 5%；同时报告多次测试的波动 |
| 纯拖动且无流更新 | 消息子树不因坐标变化额外提交 React 渲染；无存储写入和网络请求；一次落下最多保存一次 |
| 4 面板并行 | 60Hz 设备目标接近 60fps，拖拽帧耗时 p95 不超过 20ms，输入到绘制 p95 不超过 100ms |
| 连接数 | 每个唯一 session 最多 1 条详情流，全局 1 条索引流；拖动、缩放、聚焦不重连；发送和审批没有连接槽等待 |
| 开关和增删循环 | 连续切换及增删 20 次后无遗留订阅、定时器和 detached DOM；缓存达到稳定状态后内存不持续线性增长 |

基准使用相同机器、视口、生产包和固定回放数据，对比改造前普通模式、改造后关闭模式、开启后的 1／2／4 面板。包含每会话约 500 条消息、长代码块、工具调用及并行流式更新；记录实际 token 频率、CPU、堆内存和网络。Web 浏览器与桌面 WebView 分别测量。Profiler 定位渲染问题，正式时延数据使用未开启 Profiler 的生产包。
