Trace 观测与插件设计

Trace 界面按 Multica 对应页面完整还原，采集通过可选插件接入，执行语义继续由 ADK 内核负责。

建议采用：Observer 插件 + 通用事件补齐研究基线：工作区 HEAD 7e4760b + 当前未提交改动

本文是调研与技术方案；拟新增的插件、事件字段与 HTTP 接口尚未落地。T2 已从 Multica 官方仓库定位实际 Transcript 组件，按固定提交重做离线交互原型。视觉验收目标保持与原组件一致；原型完成源码尺寸与交互核对，尚未完成原版运行截图的逐像素比对。

可以作为 Plugin 接入，但要分清三层能力

建议新增独立包 @alpha/adk-trace。它通过现有 PluginAPI.observe() 旁路采集事件，构建 span、异步写入独立存储；AlphaCode daemon 组装查询服务，Web 以独立 Trace 面板展示。内核只补充可复用的观测事实，不依赖 Trace 包、SQLite 或 OpenTelemetry SDK。

ADK 插件
使用现有 plugins: [...] 静态组合，支持不带 Session 的普通 ADK Agent。不占用 RunBoundary，不改变模型、工具、审批或消息历史。
应用适配
把 project / session 归属、用户审批区间、Session 保存结果和工具业务结果接入 Trace 服务；这些信息由应用提供，不能从纯 core 事件里臆造。
前端功能
首版在 AlphaCode Web 中增加按需加载的 features/traces；Trace 区域以经确认的 Multica 页面为视觉与交互标准，现有组件仅在呈现一致时复用。当前没有通用 Web 插件宿主，采集插件不会自动安装前端面板。
路径收益限制 / 代价判断
只用现有 observe零内核变更，立即获得 run / model / tool 的起止轮廓只能记录接收时刻；缺请求关联、模型身份、逐调用 usage；审批与保存不可见适合验证原型
Observer + 小幅事件扩展清楚的事件来源、准确关联与耗时；保持内核依赖方向需要补充公开事件字段和兼容测试推荐生产首版
包裹 Model / Tool / prompt可以读取部分输入输出容易漏掉拒绝、prepare 失败、Session 重放与提前取消；复杂装饰器影响执行路径仅专项扩展
直接以 OTel SDK 作为内核标准导出生态引入全局上下文、SDK 与导出器；不直接解决本地查询、运行中更新和 Session 语义后续可选导出层
首版范围：单进程本地 Agent；一轮真实执行对应一条 Trace；运行中与历史查询；双轨时间线和步骤明细联动；类型 / 工具筛选；独立存储；元数据导出。多 Agent 因果链、跨服务传播、独立完整 payload 归档、费用账单和任意第三方 UI 插件留到后续。

工具与详情

连续 ≥3 次同名工具折叠；包含 command 的 shell 调用保持逐行。点击子项或普通步骤，在 416px 右栏展示输入、结果；长内容以“显示全部”展开，修改内容展示 diff。

检索与排序

搜索当前运行；筛选按消息类型与具体工具多选。更多菜单提供正序 / 倒序、全部 / 筛选结果复制。默认正序，无选中详情。缩放控件在悬停、聚焦或放大后出现。

为什么拆出展示层，而不嵌入整个 Multica

Transcript Dialog 依赖 Multica 的 task、消息流、i18n、store、富文本、Dialog / Popover 与平台工具。直接嵌入整个应用会把其运行模型带进 Alpha。建议移植这一组展示组件与纯转换函数，并通过 TraceViewAdapter 提供等价数据；ADK 采集仍保持独立 Plugin。

把事件的时间和关联补齐

先保持现有 AgentEvent 的事件种类，追加可选的 telemetry 元数据；Plugin.apiVersion 继续为 1，观测载荷单独带 version: 1。核心 producer 保证新模式完整，插件仍容忍旧事件。避免用新增 union 成员突然打破所有穷尽 switch。

时间语义必须一致

  • Span duration = endElapsedMs − startElapsedMs；不使用系统日期相减。已结束 span 不因系统校时而出现负耗时；live span 可在前端短暂外推，但离线即冻结并提示数据过期。
  • 首段文本延迟 = 第一条非空 model.delta − model.start。当前只有文本增量，不能把它称为所有模型的精确 TTFT；纯 tool-call / 无文本时显示“未报告”。不存储 delta 正文，也不按 token 建 span。
  • 工具耗时 是 tool.start 到 tool.end 的 gateway 区间，可能包含结果映射与提交。人工审批由应用单独计时；其他校验、policy、beforeModel 等空隙显示“未分解”，不自动归因为推理或网络。
  • 总耗时 是 run.start 到 run.end；各 span 之和不能直接当总耗时，父子与并发会重复。首版工具虽串行，数据模型仍支持重叠。
  • 保存耗时 不属于 core.run。P1 仅展示 Session 的 saved / unsaved 状态和回执时间；需要 admission / persistence 全链路计时时，再引入独立的应用 invocation 根节点。

Span 归属与异常配对

模型、工具、审批均挂在 run 根节点下。工具通过 links: caused_by(modelSpanId) 关联生成它的模型；审批通过 relatedToolKey 指向工具调用。模型通常早于工具结束，不能把已结束的模型调用当作包住后续工具执行的父区间。

模型键为 (agentId, runId, modelCallId)；工具键为 (agentId, runId, assistantId, callId)。只有 tool.end 的 rejected / not_executed 调用以事件点显示，durationMs = null，保留 missingStart；未开始的调用绝不画成“耗时 0ms 的成功工具”。如果后到的数据补齐起点，则幂等更新。

状态不压成一个布尔值

completed、refused、limited、incomplete、unknown、cancelled、failed 保留原意。Trace 中断不改写已知 RunResult；业务执行完成、会话未保存与 Trace 丢数据可以同时存在。

execution=succeeded 只代表工具实现返回。Coding 工具可能返回 ok:false 或非零 exitCode；应用解析后记录 businessStatus=error。UI 显示异常，但保留原 execution 供排障。未知工具没有适配器时不猜测内容语义。

Usage 与费用

仅累计 model span 已报告的 input / output tokens；根节点的 RunResult usage 只用于核对，不再次求和。缺失保持 null，部分上报显示“已报告，2 / 3 次”。当前 Provider 没有缓存 token 分项，首版不虚构缓存收益。

原型金额为模拟 fixture，用于验证原组件 usage chip。P1 只显示已知 usage，不提供未经计价的金额；费用缺失时保留原组件的未知值呈现。后续金额必须带价格版本、币种与估算标识，未知价格显示“不可估算”。标题生成等非 ADK 调用不混入当前 run；如需计量，应单独归类为应用调用。

接入 API：像 Session 一样组合，职责各自独立

下例是拟新增 API 的调用草案，用于评审组合方式。核心工厂仍只有 createAgent() / 现有 createCodingAgent()；不引入 trace.prompt() 作为第二套执行入口。

import { createAgent } from '@alpha/adk/core';
import { createSessionPlugin } from '@alpha/adk-session';
import { createTraceService, createTracePlugin } from '@alpha/adk-trace';
import { createSqliteTraceStore } from '@alpha/adk-trace/sqlite';

// daemon 级资源；数据库打开失败由应用降级到 memory / disabled 并报告健康状态。
const store = await createSqliteTraceStore({ filename: './traces.db' });
const traces = createTraceService({ store, capture: 'metadata', flushIntervalMs: 250 });
const tracePlugin = createTracePlugin({
  service: traces,
  scope: { namespace, projectId, sessionId: session.id },
});
const agent = await createAgent({
  model, instructions,
  plugins: [createSessionPlugin({ session }), tracePlugin],
});

// 在应用边界订阅，不让 adk-trace 直接依赖 Session 包。
const unsubscribe = session.subscribe(event => {
  traces.recordSessionEvent({ namespace, ...event });
});
try {
  const result = await agent.prompt(input, { requestId });
  // session/request → run 的映射由增强后的 run.start 建立。
  // 同 requestId 重放不会产生第二条执行 trace。
} finally {
  await agent.close();                 // 停止生产事件，释放插件
  unsubscribe();
  await traces.flush({ timeoutMs: 2000 }); // 返回 saved / degraded 结果，不替换业务结果
  await traces.close();                // 仅 daemon 总退出时；内部关闭 store
}

已有接口无法覆盖的桥接

  • 审批：在 createRuntime 的 approve(action, ctx) 回调外层记录开始，在 finally 记录结束；使用 ctx 的 runId、assistantId、callId。只有用户等待才标为 approval，不能把全部 authorizeTool hook 耗时当成人工审批。
  • 工具业务结果：在现有结果解析处分离一个共享的纯解析函数，向聊天记录和 Trace 提供同一 businessStatus / exitCode / errorCode。应用桥接读取正式结果后只发送小型摘要；插件不持有可写 Agent 历史。
  • Session：订阅已有 saved / unsaved，通过 scope + requestId 找 run。重放时查询已有映射和保存结果；找不到 Trace 说明原执行未采集，不反向“补造”模型耗时。
  • 内容详情：首版记录 messageId 等引用。允许用户查看现有会话的正式消息时，由应用侧鉴权后按引用读取；纯 ADK 无 Session 时显示“未采集正文”。这不是 Trace 自己的 raw payload 采集开关。

插件生命周期与失败策略

setup() 只注册同步 observe；回调做有界的元数据复制与入队。start() 仅建立轻量订阅，不进行可能导致 createAgent 失败的外部网络连接。Service 资源在应用启动阶段准备；插件实例禁止跨 Agent 复用。dispose() 清理本实例映射并有限等待排空，错误进入 Trace health；不把存储失败抛成业务异常。

类型 / 配置错误在创建阶段显式报错；数据库不可用默认 fail-open，应用可选择 memory-only 或禁用 Trace。关闭超时、导出失败和队列丢弃都要可观测；“不影响业务”不等于“悄悄丢失”。

独立存储，接受有边界的观测损失

建议使用独立 ~/.alphacode/traces.db，不修改 Session 的归档 formatVersion=1。生产写入由 Bun Worker 持有 SQLite 连接执行，避免同步 bun:sqlite I/O 卡住 Agent；memory adapter 用于离线测试。具体参数是首版默认值建议，需用压测确认。

写入与恢复

  1. observer 生成稳定 eventId：core 使用 agentId/runId/seq，应用桥接使用独立 source 的 ID。只留首条文本到达时间与计数，丢弃 delta 内容；大对象不进入队列。
  2. 共享有界队列建议最多 4,096 条或 8 MiB；每 250ms 或 128 条批写。数据库事务内同时写 records、更新 spans / runs 和 revision；提交后才推进 persistedRevision。
  3. 溢出优先移除可合并的进度信息，给 start/end 留容量；仍超限时丢弃并标记 captureStatus=partial，明确 droppedEvents。每 run 内存索引也必须有上限，不能因数据库批处理而忽略 reducer 内存增长。
  4. 数据库短暂故障指数退避，重试幂等；持续失败切换 degraded，保留有限内存视图。正常退出有限 flush；强制终止可能丢失最近一个批次，不能承诺审计级零丢失。
  5. 启动时仅恢复已确定不再存活的本地 producer 所属未闭合 trace；单 daemon 模式通过实例锁确认所有权。记录 captureStatus=interrupted、未闭合 span status=unknown，不伪造成功或精确结束时刻。

Session 是业务结果的权威来源，Trace 是可缺失的观测记录，两库不做跨库事务。若 Session 有保存结果而 Trace 缺尾事件，可补充“已知运行结果”，但耗时与 span 完整性仍标为缺失。旧会话没有 Trace 数据时，展示“该轮未启用采集”，不从消息排列推算历史时间线。

容量与清理

建议默认保留 7 天、1 GiB 上限，按已结束 trace 整体清理；活跃 trace 不在运行中清除。先清理 records、后删除整条 trace 时保留 schema 一致性；导出以一致版本读取。单 trace 超过建议 10,000 spans 或 8 MiB 元数据时停止新增明细，保留汇总与 partial 标记。Session 删除流程同步发起该作用域 Trace 清理，失败可重试；不能依赖跨库外键。

HTTP 读取数据，SSE 只通知版本变化

沿用现有 daemon 的 Host / Origin / 本地客户端校验。当前 SSE 是最新快照流，首版选择版本通知 + HTTP 拉取，不额外引入持久事件总线。以下全部为拟新增路由，不是已有接口。

重连、分页与一致性

  1. 先连 SSE，服务端总是发送当前 revision；再请求该 revision 的 summary / spans，避免初次 GET 与订阅之间丢变化。每次收到更大 revision 都让查询失效，旧请求带 AbortSignal 取消。
  2. SSE 允许跳版本，因为 HTTP 返回的是投影快照。断线重连重新拉取最新 revision；instanceId 改变时清除旧游标和进程内缓存。这里不依赖 Last-Event-ID 回放。
  3. 分页 cursor 包含 revision、过滤器摘要和排序键。对运行中的 trace 使用 revision 栅栏：服务端只接受仍有效的版本，否则返回 409 TRACE_REVISION_CHANGED，客户端重取第一页。对高频长 trace 可暂停跟随并申请短期快照，P1 不假装多页天生原子。
  4. 顶部 run 摘要与步骤明细分离；筛选只作用于步骤列表，完整时间线保留运行上下文。timeline 返回全程区间聚合，steps 按 cursor 分页；服务端返回正确总量 / 截断信息，不能只搜索浏览器已加载的一页。跨页分组必须由服务端稳定 groupId / count 或连续边界游标支持，不能每页单独凑组。
  5. SessionId、traceId、spanId 都需逐级校验归属；不能让用户传任意 namespace 或文件路径。未授权或跨项目访问统一拒绝，不靠难猜 ID 作为权限。

前端继续使用现有 TanStack Query，缓存键至少包含 sessionId、traceId、revision、筛选条件。只订阅当前打开的 Trace；离开页面关闭连接。此方案不改变现有聊天 SSE 协议版本 2，可在能力字段中声明新 Trace API 版本。

内容读取与采集边界

Trace 默认只落盘结构化元数据，不复制 prompt、模型正文、工具参数、文件正文或凭证。完整界面内容由正式 Session 消息按引用读取；这条只读路径沿用会话权限，响应做脱敏与字节限制。纯 ADK 的未采集内容显示原因，不填入示例值。

采集错误摘要使用白名单；name 长度、属性数与字节数设上限。后续独立 payload 归档需显式配置、入队前脱敏与裁剪。生产 React 组件按文本或安全 Markdown 渲染任意工具输出，不能直接把输出交给 innerHTML；图片仅接受已验证媒体数据。导出与预览采用同一脱敏规则。

上线与回退

配置建议 trace.enabled 初始 opt-in；启用后默认全量采集结构化元数据，采样粒度为整个 run。发布时先验证终端与 Web 共用的 daemon 路径，再开放界面入口。关闭插件即停止新增采集，已存数据仍可只读；数据库迁移仅向前、备份后执行。TraceService 或查询模块失败不影响原聊天功能。

本方案建议锁定的决策：采用独立 Trace 包；允许少量 core 观测字段扩展；保留独立 SQLite；P1 元数据优先；前端按需加载；后续再加 OTLP。UI 固定对齐 Multica Transcript 提交 10f0ab3。插件可行性由本仓库源码支撑；UI 以固定提交及同 fixture 截图验收。内容缺失状态保留真实语义。
