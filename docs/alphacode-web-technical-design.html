AlphaCode Web 前端技术设计

现状更新（2026-11-09）：本文保留为历史设计，不代表当前实现。终端与 Web 已统一迁移到 React，Web 目前是空白 React + Vite 脚手架；独立客户端包已删除，CLI 所需的协议与 HTTP/SSE 实现保留在 apps/alphacode/src/server/，聊天契约位于 apps/alphacode/src/chat/contracts.ts。下文的旧技术栈、共享包拆分与 UI 方案不再作为当前实现约束。

第一版是现有 TUI 的浏览器客户端，不是另一个 Agent，也不是浏览器 IDE。保留对话、工具、审批与保存语义，让 /web 打开同一会话。

设计日期：2026-11-08 · 技术：SolidJS + Ark UI + Vite · 范围：本地单用户 · 状态：建议方案 + 最小 starter

本轮交付：完整前端设计、参考项目分析、官方模板适配后的独立前端包。未交付：daemon、HTTP/SSE、真实会话、认证、/web 启动命令。现有 D1 文件是设计与离线模拟，不是已可调用的后端。

01 结论与边界

一个执行核心

daemon 持有运行时、会话、权限与保存；TUI / Web 都是投影与命令入口。

独立 DOM 构建

新增 apps/alphacode-web；与 OpenTUI 共用 Solid 版本，但不共用 JSX renderer 或 UI 组件。

先闭环再扩展

优先保证同一会话、断线恢复、不重复执行；文件树、终端、diff 不挤进首版。

议题选择理由及代价
应用形态Vite SPA，不用 SolidStart / SSR本地受保护工具，无 SEO 或首屏服务端内容需求；复用 daemon 托管，避免再维护一套服务端。
交互与样式Ark UI Solid + 原生 CSS 变量；业务组件用 CSS ModulesArk 管复杂交互，不是完整主题。自行维护少量语义 token；当前壳只有全局 CSS，按需演进。
传输HTTP 命令 + Fetch SSE 事件流顺应 D1；首版没有终端双向字节流，不引入 WebSocket / tRPC / 通用事件总线。
状态框架无关投影 + Solid store 适配唯一事件入口，命令回执和流状态分开。P0 不额外引入 Redux、Zustand 或 Query 缓存。
路由业务阶段使用 @solidjs/router只在实现 session URL 时添加；starter 尚未安装或声称存在业务路由。
会话入口/web attach 当前会话，不新建 Agent本轮仅规定交互合同；需要 daemon 和 TUI 的 RemoteChat 改造先完成。

非目标：公网/局域网服务、多用户、云同步、账号系统、移动原生应用、Monaco、PTY、文件树、编辑器级 diff、浏览器安装插件、任务队列、多 Agent、模型切换、后台定时任务、PWA 离线执行。不会为了 Web 重新实现权限判定、Skills 展开或 Session 落盘。

02 以现有 TUI 为基线，而非想象功能

依据当前 apps/alphacode/README.md、chat/contracts.ts、chat/controller.ts、runtime/history.ts 与 runtime/skills.ts。产品 UI 延续英文，设计说明使用中文；模型回复语言不由 UI 限制。

能力TUI 当前事实Web 首版承诺
输入与对话多轮、Markdown、流式文字；同会话单轮执行Enter 发送，Shift+Enter 换行；生成时可编辑草稿但不入队；刷新不自动发送。
工具过程状态、命令/路径、返回输出；没有实时 stdout；新轮会清除上一轮工具展示首版展示当前/最近一轮工具，保留全部状态与截断提示；不冒充 terminal。跨所有历史轮工具树属于后续扩展。
确认操作命令预览 + 单次允许/拒绝底部待审批卡片 + 明确按钮；展示 shell、cwd、command。不会用页面任意 y/n 按键授权。
权限ask / auto / full；保存后生效；忙碌时不能改完全相同的服务端语义，修改期间禁用发送；Full access 额外确认 UI 不能替代权限校验。
Skills/skills 本地目录与诊断；/skill 参数保留原始空白；// 转义；未知命令本地拒绝命令面板与只读 Skills 对话框；最终展开、信任校验、字节限制均在 daemon；不向浏览器分发 Skill 正文。
取消Esc / Ctrl+C；取消后保留不完整预览Stop 按钮；Esc 先关闭浮层再考虑停止；不劫持浏览器 Ctrl+C。
保存落盘完成才能下一轮；保存失败和未知执行阻塞Completed 与 Saved 分开；Unsaved 仅重试保存，不重跑模型/工具；Recovery required 禁止继续。
会话元信息模型、工作区、会话标题；ALPHACODE_SESSION 恢复；没有历史选择 UI 或模型切换P0 显示当前会话；P1 增加已授权工作区内的历史选择与新建。不能把这些写成现成功能。
重要差异：现有 Chat.close() 会取消并保存本地 runtime；它不是浏览器的 detach。页面关闭、路由切换或网络断开只能停止订阅，不能调用 close / stopDaemon。共享 daemon 前，不承诺 TUI 退出后执行仍继续。

03 开源项目调研及取舍

这里将用户提到的 “deepharness” 按 DeepSeek Harness 理解。依据上游工程与架构文档，不把未运行的界面当成已完成视觉审计。以下链接的主分支内容会变化，结论是 2026-11-08 的读取快照。

DeepSeek Harness：借鉴状态与生命周期，不复制插件平台

它的 Web 架构是 React + Cordis 插件组合，明确分开 Host 权威状态、Remote 传输、框架无关 Client models、UI adapters 与呈现层。会话 follow 的开头给出完整基线，重连按 generation 替换投影；其物理传输是 WebSocket，不能据此声称它使用 D1 的 SSE。[S1]

共享 store 提供不依赖 React 的快照、订阅与按帧发布能力。[S2] 本项目采用：服务端是唯一真相；组件不直接管重连；高频文字更新和 UI 发布分离。不采用：Cordis 容器、动态模块图、Slots 插件系统、通用 RPC 网关或浏览器插件加载器。AlphaCode 首版功能边界固定，复制平台机制只会扩大维护面。

OpenCode：最贴近本项目技术栈的工程参考

当前 @opencode/app 使用 Solid、Vite、Router，并拆出 client、schema、session-ui 和 ui 包；清单中也包含 Query、虚拟列表等较完整产品依赖。[S3] client 根入口是基于 fetch 的 Promise API，并通过边界测试隔离服务端/核心运行时。[S4]

本项目采用：前端独立包、窄 browser-safe client、会话视图分组件、按需加载重型呈现器。不采用：整包 fork、其 Kobalte 组件体系或立即复制所有 UI 依赖；我们已确定 Ark UI。它的分包是规模化参考，不意味着首版也需要同样多的包。

可借鉴设计AlphaCode 落地刻意删减
Client model 与 view 分离SessionProjection + SessionProvider；TUI 可复用 reducer 测试不共享 DOM/OpenTUI 组件，不强迁移全部旧控制器
完整基线后接增量state.snapshot / stream.reset + cursor不做浏览器自己的第二套会话数据库
对话与工具信息分层主对话时间线 + 折叠工具卡 + 待审批操作区不把所有诊断默认展开成 IDE 面板
客户端资源有明确 owner每个活动路由一个连接 owner，onCleanup 仅 detach首版不搞跨标签页 leader election / BroadcastChannel

区域交互约束组件选择
Composer受控纯文本 textarea；4–8 行自增高；按会话内存草稿；断线可编辑不可提交；浏览器刷新不持久化正文原生 textarea / button；不引入富文本编辑器

快捷键优先级：IME → 活动 Dialog/命令面板 → 文本选择/输入 → 会话动作。Esc 关闭浮层时不再冒泡取消任务；无浮层且执行中才停止。Ctrl+C 保留复制。审批不抢焦点；Tab 顺序、focus restore、触屏目标、减少动画都要真实浏览器验收，不能仅因用了 Ark 就宣称可访问性已通过。

消息区域可作为日志区域，但不逐 token 向读屏器播报。只礼貌播报“开始 / 等待确认 / 完成 / 保存失败”等状态；复制按钮有文字标签。主题跟随系统，后续可保存 light/dark/system 偏好；不在浏览器存储模型密钥、会话正文或工具输出。

07 D1 协议能支持什么，还缺什么

依赖基准：daemon D1 设计、D1 类型草案。这些文件保持原样。本节是 F1 前端要求的后续协议修订建议，不能在实现时直接假定已存在。

动作D1 接口 / 路由前端处理
启动认证POST /api/v1/auth/exchange一次性 launchCode 换 cookie + 内存 CSRF
读取能力GET /api/v1/daemon校验 apiVersion、instanceId、capabilities
会话基线GET /api/v1/workspaces/{wid}/sessions/{sid}/events首帧 state.snapshot；不用独立 GET 与订阅拼凑无竞态启动
发送 / 查询 / 停止POST S/requests；GET S/requests/{rid}；POST S/requests/{rid}/cancel稳定 requestId，202 仅受理，取消也需权威结算
审批POST S/approvals/{aid}/decision携带 requestId + runId + decision；服务器绑定 toolCallId
权限 / 补写PATCH S/settings；POST S/persistence/flushexpectedRevision 并发控制；flush 不触发 send
历史 / 会话列表GET S/messages?before=…；GET W/sessions旧消息分页；列表只在授权能力具备后开放

S = /api/v1/workspaces/{workspaceId}/sessions/{sessionId}；W = /api/v1/workspaces/{workspaceId}。所有路径段编码，不能用字符串拼接未校验工作区路径。

合并前必须补齐的契约缺口

缺口为什么会阻塞等价体验建议修订（尚未实现）
刷新后的 CSRF 恢复D1 只在一次性 exchange 回 CSRF；fragment 清除后刷新没有可再次消费的 code新增 GET /api/v1/auth/session，基于有效 cookie 返回会话信息、CSRF、能力和授权范围；失败提示从 TUI 再次 /web，不循环 exchange
模型 / 工作区 / SkillsSessionSnapshot 无 modelId，缺少 Skills 元数据与加载诊断新增 GET S/context，返回冻结 runtime 的 modelId、workspace 展示信息、skills、diagnostics、contextRevision、输入字节限制；重启/重新绑定后重取
工具关联与完整状态WireTool 缺 queued/failed、assistantId、callId、输出截断、cwd 等；不能还原现有 TUI扩充 Tool DTO：assistantId、callId、callIndex、description/source、target、path/cwd、全部 ToolStatus、error/exitCode、truncated/omittedLines/outputIncomplete、startedAt/finishedAt
消息顺序与历史边界仅 id + requestId 不能从分离的 messages/tools 确定呈现顺序；分页响应可能晚到WireMessage 增加稳定 ordinal 与不完整原因；工具挂到 assistantId 并按 callIndex 排序；分页附 instanceId + snapshotRevision，限定请求的 session/generation
轮次结果与计时请求仅 acceptedAt/finishedAt，无法等价显示恢复后的模型执行耗时；终态不必然成功增加 startedAt、durationMs，以及最近一轮 completion；outcome 与 execution 分离，durationMs 服务端计算并持久化
准入状态更新eligibility 仅在 snapshot；saved/settings_changed 只给少量字段，UI 容易一直 busy 或错误放行新增 session.state_changed { revision, eligibility, activeRequestId, settingsSaving }，在准入改变时发布；所有 revision 不倒退。P0 若未增加，就变更后以原子快照重新同步，不自行猜 ready
回执与 SSE 竞争旧 HTTP 回执可能覆盖流上已经保存的新状态mutation receipt 附 serverCursor；只确认本地 intent，不覆盖比它新的投影。GET snapshot 不作为随时覆盖流状态的捷径
浏览器授权范围BrowserSession.target 不是完整 ACL；无法推断可以列举所有 workspace显式 session-scoped grants 与可执行 capability；P1 workspace 授权另行由 native 用户意图授予，前端不能通过路由参数扩权

Tools 历史边界：P0 同 TUI 仅保留当前/最近一轮工具投影，旧用户和助手消息按 ordinal 分页；不声称能分页全部历史工具。若 P1 要展示全历史轨迹，再给消息页增加对应工具或引入统一 TimelinePage，并明确预算与稳定排序，不能混用不完整的 snapshot.tools 拼历史。

  ref, instanceId, appliedCursor, revision, eligibility,
  activeRequest, permissionMode, settingsSaving,
  messageIds, messagesById, toolsById, approvalsById
}
BrowserGrant = session refs + explicitly granted capabilities
MutationReceipt = existing receipt + serverCursor

这些修订由 daemon/client 共用 schema 和契约夹具一起落地。不得直接把文档 .d.ts 通过路径别名当成稳定发布 SDK，也不能用强制类型断言绕过 runtime JSON 校验。破坏性改变递增 API 版本；新增可选功能用 capability 协商。旧服务端缺必需能力时给出版本不兼容提示。

08 状态管理：三个层次，四条状态轴

层次数据写入者
服务端权威投影消息、工具、审批、request、revision、eligibility、权限唯一 SessionProjection reducer；快照和有序流进入同一通道
客户端 intent待发输入的 requestId、提交中、回执未知、审批决定提交中、settings mutation命令 service；不冒充服务端 request 执行结果
局部 UI 状态草稿、面板开合、选中工具、滚动锚点、主题组件 / route owner；不从它推断任务完成
connection:  booting → authenticating → syncing → connected
                         ↘ auth_required / incompatible
                                      connected → reconnecting → syncing
execution:   idle → accepted → running ↔ awaiting_approval → terminal
persistence: pending → saved | unsaved | recovery_required
mutation:    idle → submitting → confirmed | rejected | outcome_unknown

canSend = connected AND authoritative eligibility == ready
          AND no active request AND no pending mutation
          AND no pending approval AND valid nonempty input

Completed + pending persistence → “Saving session…” → no Send
Completed + unsaved             → “Not saved” → Retry save only
Recovery required              → read-only + explicit recovery guidance

busy、按钮可用性和状态文案从状态轴派生，不再另存五套可能矛盾的布尔值。运行计时依据服务端 startedAt/durationMs；客户端单调时钟只用于当前页面内动画，重连后校正。不要跨进程比较 performance.now()。

网络 reducer 保持框架无关；按实体 ID 输出局部 patch，再由 Solid batch 写入 createStore。消息顺序用稳定 ID 列表，组件 key 不用数组下标；保留未变化实体引用。不在每个 token 克隆整个 ChatState，也不在多个组件各自保存一份消息数组。

snapshot/reset 原子替换服务端投影，保留同会话未提交草稿；抛弃旧连接的缓冲增量、审批 pending intents 和旧页响应，随后查询回执未知的 request。历史读取捕获 routeGeneration + instanceId + revision，返回时不匹配则丢弃。组件 onCleanup 释放 stream、监听、计时器和 render buffer，但不取消后台请求。

09 流式、重连与并发正确性

启动和恢复

  1. 读取并立即清除 fragment 中的 launchCode，交换浏览器 cookie；无 code 的刷新走新增 auth/session。成功后校验 daemon 版本与授权目标。
  2. 创建 routeGeneration 与 AbortController。读取 session context，同时打开该会话 SSE。只有合法的 state.snapshot 应用完成才从 syncing 变 connected。
  3. 每帧校验 envelope：workspace/session、instanceId、event type、payload、sequence/cursor 对应关系与大小预算。同实例已应用 sequence 的重复帧丢弃；不连续或未知语义帧触发重新同步，不能继续盲目追加。
  4. 断线保留可读投影，但暂停发送、审批和设置。重连仅携带最后已应用的游标；不是最后收到、但还没写入投影的帧 ID。
  5. 服务器回 replay 则有序补齐；回 stream.reset 则原子覆盖快照。instanceId 改变时所有旧 pending 状态失效，不能向新实例重放旧审批。

选择 Fetch SSE：统一 Promise/AsyncIterable client，可读取 HTTP 状态、实现 AbortSignal 与可控退避；采用成熟 eventsource-parser 类解析器，不用 split("\n\n")。按照 SSE 标准处理分块 UTF-8、CRLF、多行 data、注释心跳、id、retry 和未完成尾帧。[S9] 浏览器原生 EventSource 也是可行替代，但两套实现不要同时成为状态来源。

建议退避 0.5s、1s、2s、4s，最大 15s，加 jitter；遵守 Retry-After。401 转 auth_required；403、协议不兼容和非法 payload 停止自动重试并展示明确错误；网络错误及明确可重试 5xx 才退避。D1 提议 15s 心跳，前台连续约 45s 无任何字节则重建连接；后台标签页恢复可见时主动校验，不把计时器被节流误判为任务失败。

发送幂等与回执丢失

  1. 点击发送立即冻结输入与 UUID requestId，先标记本地 submitting，防止双击和重复 Enter。乐观用户行用 requestId 关联，但标记“Sending”，不是伪造已保存消息。
  2. POST 202 只表示 accepted。SSE 的 request.accepted 可能先于 HTTP 返回：按 requestId 合并，用户行只能有一条。
  3. 若 POST 超时，标记 outcome_unknown；先查询同 requestId。查询存在就 attach；确定不存在且仍为同 daemon/grant 时，才允许同 ID、同输入重试。不可换 ID 或重新展开 Skill。
  4. 旧回执只更新 intent，不覆盖已前进的 execution/persistence；Saved 状态不得被晚到的 accepted receipt 回退。
  5. 刷新不恢复自动发送。可在 sessionStorage 保存最小 receipt locator（instanceId + ref + requestId，不含输入）用于查询；实例改变时仅做恢复提示，绝不自动重试执行。

多端审批、取消与设置

审批决定绑定 approvalId/requestId/runId；服务器 first valid decision wins。另一端已批准，当前端的反向决定收到 409 后显示“Handled in another client”，重新读取权威状态；过期收到 APPROVAL_EXPIRED，不能复活按钮。断线不等于批准；不预先把工具标成 succeeded。

取消仅发送对当前 requestId 的明确操作；按钮进入 Stopping，等 request.finished 与持久化结果。关闭标签页、切换会话、SSE abort 均不会触发 cancel。权限修改携带 expectedRevision，409 回滚选择并重新同步；保存成功前不改变生效权限。

首版每个标签页一个活动会话连接；用户切换会话时取消旧订阅。两个标签页各自可读同一会话，写操作由服务端 single-writer + 幂等保护，不做前端选主。会话列表 P1 先在进入、focus 与操作结算时重新读取；没有列表事件就不宣称后台列表实时。

10 本地认证、信任边界与安全

/web 的握手合同

TUI /web
  → 确认唯一 daemon 与当前 session runtime 所有权
  → native 凭证请求一次性、短时、目标绑定 launchCode
  → 仅在服务就绪后打开浏览器 /w/{wid}/s/{sid}#launch=...
Browser
  → 读取 code，立即 history.replaceState 清除 fragment
  → POST /auth/exchange → HttpOnly cookie + CSRF + grants
  → GET /daemon + S/context → S/events → 原子 snapshot
Refresh
  → GET /auth/session（F1 新增建议）→ 恢复 CSRF → 重新订阅
Close tab
  → detach only；daemon 与任务继续

TUI 已有 Slash 命令注册与 Skills reservedNames 必须加入 web，在 UI/命令层截获，不能把 /web 发送模型。它是独立于聊天发送的本地操作：即使任务执行中也可以 attach，不受 chat.canSend 的发送门槛限制；这需要单独的命令分发路径。若启动时 runtime 仍属 TUI 进程，必须先完成 daemon 化；不通过新建同 ID runtime 或启动第二个进程来“模拟共享”。

  • 生产仅 loopback、单一 browser origin；精确 Host/Origin 校验与授权作用域由后端负责，前端隐藏按钮不是 ACL。
  • launch code 放 fragment，不放 query、日志、analytics 或本地存储；默认沿 D1 60 秒、单次消费。交换响应不可缓存，禁止 service worker 缓存认证和会话。
  • HttpOnly、SameSite=Strict、host-only cookie；HTTPS 时 Secure。cookie 不隔离端口，必须防止另一本地服务被误信任。写操作带 JSON Content-Type 与 X-AlphaCode-CSRF；不开放通配 CORS。
  • 认证刷新 GET 只向同源可见，校验 Host、Origin/Fetch Metadata；不要把 CSRF 挂进 HTML 或 URL。重启令 cookie 失效时要求重新 /web，而不是退回无认证模式。
  • 多标签页 launch 交换应保持同一 browser session 的既有 grants，原子加入明确的新目标；不能静默覆盖 cookie 的唯一目标使旧标签页失效。若轮换 CSRF，写失败后经 auth/session 重新取值，不能盲目重放审批。
  • 普通浏览器不能注册任意工作目录或 stopDaemon；P0 只访问 launch 授权的 session。P1 列表与创建权限通过 native 明确授予，不从路由推断。
  • 模型 API key、配置文件、完整 Skill 指令、原始 Error stack 不进入 bundle 或 bootstrap；VITE_* 只允许公开构建信息。前端不 import Provider、Coding Agent、Session SQLite。
  • 消息、路径、工具输出都是不可信文本；默认禁 raw HTML、任意 SVG/iframe 与外部图片自动请求。允许的外链先验证 http/https，开启新标签时 noopener/noreferrer；拒绝 javascript/data/file/vscode 等链接自动执行。

生产响应头建议：Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self'; connect-src 'self'; img-src 'self'; object-src 'none'; frame-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'，并加 nosniff、no-referrer。若某个 Ark 定位组件确需 inline style，只在明确审核后放开 style-src-attr，不放开 inline script。当前 starter 没有 daemon 响应头，这些不是已落实的安全保证。

开发环境：当前 Vite 只展示离线壳，不代理真实 API。联调时推荐浏览器仍访问 daemon origin：daemon 在受控开发模式代理 UI/HMR 到 loopback Vite，API 由自己处理；不通过 Vite changeOrigin 伪装所有来源。HMR 的 ws/connect-src 仅开发开放，生产没有例外。另一种直连 Vite 方案必须单独设计精确 dev origin 与 CSRF，不可临时禁认证。

11 Markdown、长对话与性能预算

流式内容不是每个 token 重画整页

网络帧先校验并应用到框架无关投影，应用成功后推进 cursor；只把 UI publication 合并到下一帧。对同 messageId 的增量可累计成 chunks，定期拼接，完成时由 message.committed 的完整 text 替换，绝不再次 append。结构性事件如审批/失败立即发布。后台标签页不能依赖 requestAnimationFrame 才推进协议状态；恢复可见时发布最新快照即可。

Markdown 首版采用安全 AST 渲染：稳定的已完成消息缓存 AST；当前消息约 50ms 合并解析，提交时完整重解析；未闭合代码围栏按未完成代码块显示，不执行内容。HTML 默认作为文字或丢弃；不启用 rehype-raw。代码高亮可在块闭合后懒加载，输出白名单 token span，不把模型提供的 HTML 注入 DOM。图片首版只显示链接，由用户决定访问，不发出隐含的外网请求。

不为 P0 上 Monaco、xterm、复杂 diff 或全语言 Shiki 包。若代码高亮后续需要 Shiki，仅加载业务常用语言并评估 worker/懒 chunk；纯代码块保留复制按钮即可先满足 TUI 等价体验。

分页与内存

跟随 D1 最近 50 条默认快照、历史分页；一次加载 50 条。前端建议消息工作集不超过 500 条或 10 MiB 文本（可测调优），超限优先移除离可见区最远的旧分页，并保留稳定 cursor 以供重新获取；活动轮、待审批和不明执行不得被静默淘汰。UI 裁剪不改变服务端完整历史，也不能把截断文字作为新对话输入。

单条超大输出由协议字节预算裁剪且标记；前端显示“Output truncated”，不伪装完整。P0 最近工具记录沿 TUI 语义；全历史工具轨迹先修协议再谈虚拟列表。超过 300 个复杂可见项且实测长任务超预算时，再引入 TanStack Solid Virtual；必须验证动态高度、选择/复制、锚点和读屏体验。

最值得先锁定的决定

  1. 当前会话优先：首个真实闭环不被历史管理、文件树或视觉细节阻塞。
  2. 刷新认证补齐：auth/session 和明确 grant 模型是接口前置，不留给前端临时 localStorage token 解决。
  3. 状态不做第二套真相：snapshot + cursor + 幂等 requestId + 独立 persistence 是协议基础，不是 UI 优化。
  4. 不直接复用 TUI controller：复用纯语义和测试，通过 client/RemoteChat 适配，避免 close() 误杀共享执行。
  5. 以真实双端验收：最重要的 demo 是“Web 断线、TUI 批准、Web 恢复后不重复执行”，不是漂亮的静态聊天气泡。
