01

先看我们的 API

这是拟议 API：先定义工具，再创建 Agent，最后运行。现在仓库中的 ADK 仍是骨架，以下代码暂不能运行。

01 / 定义并调用一个 Agent
import { createAgent, defineTool } from '@alpha/adk';
import { provider } from './provider.config.js'; // 已有 Provider

const weather = defineTool({
  name: 'get_weather',
  description: '根据城市名称查询天气',
  inputSchema: {
    type: 'object',
    properties: { city: { type: 'string' } },
    required: ['city'],
    additionalProperties: false,
  },
  parse(input) {
    if (!input || typeof input !== 'object' || Array.isArray(input)
        || !('city' in input) || typeof input.city !== 'string' || !input.city.trim()) {
      throw new Error('city 必须是非空字符串');
    }
    return { city: input.city };
  },
  async execute({ city }, { signal }) {
    // 换成你的天气服务；这里只返回示例数据
    return { city, weather: '晴', temperature: 22 };
  },
});

export const assistant = createAgent({
  name: 'weather-assistant',
  model: provider.use('openrouter', 'free'),
  instructions: '回答天气问题，必要时使用工具。',
  tools: [weather],
});

const result = await assistant.run('北京天气怎么样？');
if (result.status === 'completed') console.log(result.output);
else console.log(result.status, result.reason);
一次调用做什么：自动把用户输入发给模型；模型请求工具时，先校验参数并执行工具，再把结果送回模型，直到最终回答或达到终止条件。示例天气数据是假的。

公开 API：第一版到底提供什么

默认值、覆盖顺序与扩展点都写进契约。请求级配置优先于 Agent 配置；Provider 的模型限制仍然生效。

03 / Agent 与运行参数
type ModelOptions = Pick<GenerateInput, 'temperature' | 'maxOutputTokens' | 'thinkingLevel'>;

interface AgentConfig<Context = unknown> {
  name: string;
  model: LanguageModel;           // 直接接现有 provider.use(...) 的结果
  instructions?: string;
  tools?: readonly Tool<any, Context>[]; // 不同工具的输入类型可以不同
  modelOptions?: ModelOptions;    // temperature / maxOutputTokens / thinkingLevel
  maxSteps?: number;              // 默认 8，最多发起的模型请求次数
  toolError?: 'stop' | 'return'; // 默认 stop；return 允许模型看到脱敏错误
  middleware?: readonly Middleware<Context>[];
  conversation?: Conversation;  // 默认 messagesConversation()
  runtime?: Runtime<Context>;     // 默认 createReActRuntime()
}

interface Agent<Context = unknown> {
  run(input: AgentInput, options?: RunOptions<Context>): Promise<RunResult>;
  stream(input: AgentInput, options?: RunOptions<Context>): AsyncIterable<RunEvent>;
}
type AgentInput = string | readonly Message[];
interface RunOptions<Context> {
  context?: Context;             // 只给工具和 middleware，不自动发给模型
  session?: Session;
  signal?: AbortSignal;
  maxSteps?: number;             // 覆盖 agent 默认值
  modelOptions?: ModelOptions;   // 逐字段覆盖 agent 默认值
}
参数默认 / 行为边界
model必填，接收 LanguageModel 实例ADK 不读取 API Key、不创建 Provider。
instructions不传则没有额外指令每次独立运行插入 system 消息；Responses 续接时必须重新发送必要指令。
tools空数组名称必须非空且唯一；无工具时不发送 tools。
maxSteps8；run() 可单次覆盖数的是模型请求次数；第 8 次若返回工具，不执行这些工具并返回 max_steps。
toolErrorstopstop 表示停止；return 把安全错误文本发给模型，绝不把堆栈和密钥发给模型。
modelOptions不传则不覆盖模型默认值限定为 temperature、maxOutputTokens、thinkingLevel；不允许通过这里覆盖 signal / messages / tools。
session不传时单次无状态同一个 session 的并发 run 默认拒绝；历史和 context 是两种数据。
03

Tool：校验、上下文与执行

工具是普通函数加一份明确的模型输入契约。parse 的返回值才会交给 execute；TypeScript 类型不代替运行时校验。

04 / Tool 契约
type Json = null | boolean | number | string | Json[] | { [key: string]: Json };
type JsonObject = { [key: string]: Json };

interface Tool<Input = unknown, Context = unknown> {
  readonly name: string;
  readonly description?: string;
  readonly inputSchema: JsonObject; // 发给模型的 JSON Schema
  parse(input: unknown): Input;   // 运行时校验；失败时 throw
  execute(input: Input, ctx: ToolContext<Context>): Promise<Json>;
}
interface ToolContext<Context> {
  runId: string;
  toolCallId: string;
  signal: AbortSignal;
  context: Context | undefined;
}
// defineTool 让 parse 的返回类型自动流向 execute 的 input。
// 本段为简化后的对外契约；泛型 helper 的最终声明在实现时定稿。
05 / 用 context 注入应用服务
import { createAgent, defineTool } from '@alpha/adk';
import type { ToolContext } from '@alpha/adk';
import { model, orderService } from './app-deps.js'; // 应用自行提供
type AppContext = { tenantId: string; orders: OrderService };

const queryOrder = defineTool({
  name: 'query_order',
  description: '查询当前租户的订单状态',
  inputSchema: {
    type: 'object',
    properties: { orderId: { type: 'string' } },
    required: ['orderId'], additionalProperties: false,
  },
  parse(input) {
    if (!input || typeof input !== 'object' || Array.isArray(input)
        || !('orderId' in input) || typeof input.orderId !== 'string') throw new Error('invalid orderId');
    return { orderId: input.orderId };
  },
  async execute({ orderId }, { context, signal }: ToolContext<AppContext>) {
    if (!context) throw new Error('missing context');
    return context.orders.get(context.tenantId, orderId, { signal });
  },
});

const orderAgent = createAgent<AppContext>({ name: 'order-agent', model, tools: [queryOrder] });
const result = await orderAgent.run('订单 A123 状态？', {
  context: { tenantId: 'tenant-1', orders: orderService },
  signal: AbortSignal.timeout(30_000),
});
执行顺序：名称匹配 → 参数 parse → middleware 授权 → execute → 转成 JSON 字符串写入工具消息。工具未注册、parse 失败或执行失败按 toolError 处理。工具可以忽略取消信号，因此取消不保证外部副作用回滚。
04

run / stream：使用和结果

两个方法共享同一运行语义。stream 是惰性的单消费者异步迭代器；run 会消费同一套内部执行流程并返回最终结果。

06 / 实时输出与工具进度
const controller = new AbortController();
for await (const event of assistant.stream('北京天气怎么样？', {
  signal: controller.signal,
})) {
  switch (event.type) {
    case 'text.delta': process.stdout.write(event.text); break;
    case 'tool.started': console.log('开始工具', event.name); break;
    case 'tool.finished': console.log('结束工具', event.name); break;
    case 'run.finished': console.log(event.result.status); break;
  }
}
07 / 结果与事件的精确字段
type RunStatus = 'completed' | 'refused' | 'incomplete' | 'cancelled' | 'failed';
interface RunResult {
  runId: string;
  status: RunStatus;
  output: string;                // 非 completed 时可能是部分文本
  reason?: string;               // 如 max_steps、tool_error、model_error
  steps: number;                 // 本次已经发出的模型请求次数
  messages: readonly Message[];  // 本次新增消息，含必要协议续接数据
  usage?: { inputTokens?: number; outputTokens?: number };
}
type RunEvent =
  | { type: 'run.started'; runId: string; seq: number }
  | { type: 'model.started'; runId: string; seq: number; step: number }
  | { type: 'text.delta'; runId: string; seq: number; text: string }
  | { type: 'tool.started'; runId: string; seq: number; toolCallId: string; name: string }
  | { type: 'tool.finished'; runId: string; seq: number; toolCallId: string; name: string }
  | { type: 'run.finished'; runId: string; seq: number; result: RunResult };
情况状态 / reason调用方看到什么
模型完成completedoutput 为最终回答；messages 为本次新增消息。
模型拒答refused / model_refused保留模型拒答内容，不执行工具。
模型截断 / 达到 maxStepsincomplete / model_incomplete 或 max_stepsoutput 可为部分文本，不能当完整答案。
用户取消cancelled / aborted传递 signal；若工具已产生副作用，结果不表示已撤销。
模型、工具、校验、session 错误failed / model_error、tool_error、session_error返回脱敏原因；结构化 observer 留到后续阶段设计。
配置非法抛出错误无效 Agent 在创建时抛错；无效 run 参数在开始运行前抛错。
事件约定：同一 run 的 seq 从 1 递增；正常消费到结束时有且仅有一个 run.finished。文本增量是暂定内容，也可能来自工具调用前的中间步骤；最终回答以 result.output 为准。主动 break 视为取消并释放模型流，此时不保证收到结束事件；事件按需生产，消费者慢时产生背压，不无限缓存。
05

Middleware：能拦截什么、顺序是什么

第一版先明确工具执行拦截，而不是定义一组含义不清的万能插件。模型观测通过事件，替换整个调用流程通过 Runtime。

08 / 日志与工具权限
const audit = {
  name: 'audit',
  async onToolCall(call, next) {
    console.log('tool:', call.name, 'run:', call.runId); // 不记录参数
    return next(call);
  },
};

const accessControl = {
  name: 'access-control',
  async onToolCall(call, next) {
    if (!call.context?.allowedTools.includes(call.name)) {
      throw new Error('tool not allowed');
    }
    return next(call);
  },
};

const agent = createAgent({
  name: 'secured-agent', model, tools: [queryOrder],
  middleware: [audit, accessControl],
});
09 / Middleware 接口
interface ToolCallContext<Context> {
  runId: string;
  toolCallId: string;
  name: string;
  input: unknown;              // 已通过该工具的 parse
  context: Context | undefined;
  signal: AbortSignal;
}
interface Middleware<Context> {
  name: string;               // 重名在 createAgent 时拒绝
  onToolCall?(
    call: ToolCallContext<Context>,
    next: (call: ToolCallContext<Context>) => Promise<Json>,
  ): Promise<Json>;
}
规则：按注册顺序进入，逆序退出；每个 next 最多调用一次。middleware 可以拒绝、修改已校验输入或返回结果；修改 input 后，核心必须再次调用原工具 parse 再执行。单个 hook 抛错按 toolError 处理。middleware 是可信代码，不构成沙箱。

Session：聊天历史如何保存

Session 可替换，默认不启用。首版只管理消息历史，checkpoint、跨进程恢复和长期记忆单独设计。

11 / 自定义 Session 接口
interface SessionSnapshot {
  version: string;
  messages: readonly Message[];
}
interface Session {
  load(): Promise<SessionSnapshot>;
  append(expectedVersion: string, messages: readonly Message[]): Promise<void>;
  // 版本变化必须抛 SessionConflict；不得静默覆盖。
}
提交规则：run 开始读取一次快照，completed / refused 时原子追加用户输入与本次完整消息；failed / incomplete / cancelled 时不自动追加。并发冲突返回 failed / session_conflict，不自动重试工具。失败时已有外部副作用不会回滚，应用必须按业务需要处理。
07

替换运行引擎：不是只有 Hook

默认 ReAct 循环只是一个内置实现。自定义 runtime 决定模型调用顺序和工具调度，同时使用受控端口复用校验、middleware 和 step 限制。

12 / Runtime 接口
interface Runtime<Context = unknown> {
  execute(ctx: RuntimeContext<Context>): AsyncIterable<RunEvent>;
}
interface RuntimeContext<Context> {
  runId: string;
  messages: readonly Message[];
  instructions?: string;
  context: Context | undefined;
  maxSteps: number;
  signal: AbortSignal;
  model: ModelPort;      // call() 包含协议续接、参数合并、步骤计数
  tools: ToolPort;      // call() 包含 parse、middleware、工具事件
  conversation: Conversation;
}

const agent = createAgent({
  name: 'planner', model, tools: [queryOrder],
  runtime: myRuntime, // 自定义循环、路由或多个模型调用
});
13 / Runtime 使用的端口
type ModelTurn = Pick<GenerateInput, 'messages' | 'previousResponseId'>;
type ModelEvent = StreamEvent; // 来自共享模型契约；包括 text-delta 和 finish

interface ModelPort {
  // 每次调用消费一个 step；超上限抛 StepLimitError。
  call(input: ModelTurn): AsyncIterable<ModelEvent>;
}
interface ToolPort {
  // 执行指定调用：解析参数，应用 middleware，调用工具并返回 JSON。
  call(call: ToolCall): Promise<Json>;
}
interface Conversation {
  // 每个 run 创建独立状态；不得跨 run 共享可变状态。
  create(history: readonly Message[]): ConversationRun;
}
interface ConversationRun {
  first(): ModelTurn;
  next(result: GenerateResult, toolResults: readonly Message[]): ModelTurn;
}
终态责任：框架负责创建 runId、处理 session 和外部 signal；runtime 产生一个 run.finished。框架包装器检查缺失或重复终态并转换为 failed。通过 ToolPort 才会经过框架的工具校验与 middleware；自定义 runtime 直接访问外部资源不受这些规则保护。ModelTurn / ModelEvent 是共享模型类型的子集，实施前按 Provider 契约冻结。
默认 Runtime：逐步执行伪代码
// 默认 runtime 的执行顺序（伪代码，便于评审）
conversation = conversationFactory.create(history + input)
turn = conversation.first()
while (true) {
  result = await consumeModel(ctx.model.call(turn)) // 消费实时文本，读取 finish.result
  if (result.outcome === 'completed') return completed(result.text)
  if (result.outcome === 'refused') return refused(result)
  if (result.outcome !== 'tool_calls') return stopped(result)
  if (steps >= maxSteps) return incomplete('max_steps')

  toolResults = []
  for (const call of result.toolCalls) { // 首版严格顺序执行
    value = await ctx.tools.call(call)   // parse + middleware + execute
    toolResults.push(toolMessage(call.id, JSON.stringify(value)))
  }
  turn = conversation.next(result, toolResults)
}
该伪代码省略事件发送、异常映射和 session 提交，具体规则见前文。模型的 tool-call 增量事件用于展示，执行依据只有 finish.result.toolCalls，避免重复执行。
08

真实模型如何接入：续接策略明确选择

这里使用目前 Provider 已实现的字段。当前模型对象没有公开协议标识，首版显式选择 conversation，不用 Provider 名称猜协议。

14 / 三种续接方式
// 默认：OpenAI Completions 兼容服务，完整消息往返
const localAgent = createAgent({
  name: 'local', model: provider.use('ollama', 'chat'),
  tools: [weather], conversation: messagesConversation(),
});

// Responses：本次续接使用 previousResponseId + 新的工具结果
const openaiAgent = createAgent({
  name: 'openai', model: provider.use('openai', 'chat'),
  tools: [weather], conversation: responsesConversation(),
});

// Anthropic：原样回传 assistant continuation 和工具结果
const claudeAgent = createAgent({
  name: 'claude', model: provider.use('anthropic', 'chat'),
  tools: [weather], conversation: anthropicConversation(),
});
策略具体行为已知限制
messagesConversation()向消息历史追加 assistant.toolCalls 和 tool 消息。适合目前验证过的 Completions 兼容路径；厂商私有 reasoning 字段尚未抽象。
responsesConversation()读取 result.responseId；下次请求设置 previousResponseId，发送新增工具结果与必要 system 指令。要求服务端保存响应；缺少 responseId 时返回 failed，不默默丢 reasoning 状态。
anthropicConversation()把 result.continuation 原样附在 assistant 消息，之后追加 tool 消息。thinking block 和签名不得跨模型使用。
自定义 Conversation实现 create / first / next，使用每个 run 的独立状态。Provider 目前无无状态 reasoning 全量回放 API；这是后续兼容点。
responsesConversation 和 anthropicConversation 是拟议新 API，不是现有 Provider 功能。Responses 持久 session 的跨进程 / 新一轮续接还需定义 responseId 的持久化：首版先明确只支持同一 run 的工具循环，跨 run 不声称完整保留服务端推理状态。

10

Roadmap：每一步提交什么、怎样算完成

顺序围绕首个真实单 Agent 工具循环；每阶段可以单独合并并验收。

阶段具体产物验收标准
P0 · 模型契约新建 model-contract；提取现有 Message、LanguageModel 和 GenerateResult；Provider 旧路径 re-export。现有 Provider 测试与类型检查不变；新旧 import 类型兼容；无循环依赖。
P1 · 单次 Agent实现 createAgent、defineTool、run、默认 ReActRuntime、messagesConversation。mock 覆盖直接回答、1 个工具往返、多工具顺序、解析失败、未知工具、最大步数、拒答、截断。
P2 · 流与取消实现 stream、六种 RunEvent、signal 传递和资源释放。文字实时到达；错误和取消有终态；提前 break 关闭 Provider 流；run 和 stream 最终语义一致。
P3 · 真实接入接现有 OpenRouter Provider；编写天气 / 查询示例；记录模型与服务。实际跑通模型→工具→模型的非流式和流式；取消与无效 Key 可复现；不以输出文案完全一致作为唯一通过标准。
P4 · 扩展与 Session实现 middleware、内存 Session、版本冲突与可替换 Runtime。至少两种 session 实现和两个 runtime 跑同一契约测试；middleware 顺序和重入限制可验证。
P5 · 其他协议续接实现 responsesConversation / anthropicConversation 与合同测试。工具回传保留 responseId / continuation；做对应真实服务验证；跨 run 状态限制写入文档。
之后 · 按需求扩展MCP、远程工具、审批、持久 checkpoint、多 Agent、图工作流、多模态。每项先单独设计权限、数据和失败语义，不承诺仅靠现有接口完成。
11

需要先定下的四个设计决定

下面是建议的默认选择，目的是让 API 评审有具体对象。

决定当前建议为什么
工具失败默认 stop；可配置 return默认避免把敏感异常信息直接反馈模型；允许应用主动选择继续。
maxSteps默认 8，统计模型请求次数与工具数量无关，含最终模型请求；超限绝不执行尚未执行的工具。
状态与恢复首版 Session 只存成功或拒答的完整对话不把普通历史持久化宣传为崩溃恢复或 exactly-once。
协议适配首次创建时明确选择 conversation现有模型缺少协议标识，显式选择优先于依赖 provider 名称猜测。
