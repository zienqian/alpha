04 / 可以直接拆工的实施任务
每项列出依赖、改动位置与验收证据


GATE 01真实修复闭环
失败测试 → 读取 → 修改 → 批准命令 → 实际测试 → 归档 → 恢复继续。
GATE 02取消能收干净
父子进程都退出，之后才释放租约、恢复终端。
GATE 03保存不重跑
存储故障后重试保存，任何模型/工具计数都不增加。
GATE 04未知状态不绕过
重启 pending 与 blocked 只读查看，不能自动重复副作用。
GATE 05输入阅读可靠
中文与粘贴不误提交；重复 Enter 不重发；滚动不抢位置。
GATE 06应用边界明确
尊重调用 cwd；仅 bin；没有 SDK、JSONL 或服务器入口。



05 / 内部怎样组织
这些是应用实现细节，不是对外 API
apps/alphacode/src/
  bin.ts             参数 / 原始 cwd / 入口
  config.ts          固定 home YAML / Provider 选择
  runtime.ts         Agent + Session 资源 owner
  commands.ts        七个静态命令 / 门禁
  approval.ts        单次审批 / 取消清理
  session-state.ts   标题 / 上下文 / 书签
  projection.ts      消息 / 工具 / 保存投影
  text.ts            显示清理 / 宽度 / 截断
  ui/*.tsx           终端组件 / 焦点

执行：现有 agent.prompt
会话：现有 Session plugin
文件/命令：现有 Coding Workspace
模型：现有 Provider → LanguageModel
未来 app server 保留独立设计空间
package 只有 bin，不新增供消费的 exports。TUI 状态、审批桥接和生命周期函数都可以随实现调整。
之后设计 app server 时，再确定请求、事件、传输、连接与恢复语义。本版不会把 UI store 固化成服务端协议。
