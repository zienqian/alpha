一份静态配置描述多个 Provider，每个 Provider 管理自己的模型。使用时通过 provider.use(providerName, modelAlias) 获取模型，交给未来的 ADK。

Provider 首版已实现 · 示例中的模型 ID 和地址均为占位符
01

完整示例

连接配置、适配器和模型列表放在同一个 Provider 下。模型别名只在其所属 Provider 内生效。

provider.config.ts静态配置
import { defineProviderConfig } from '@alpha/provider';

export const config = defineProviderConfig({
  providers: {
    openai: {
      adapter: 'openai-responses',
      options: { apiKey: { env: 'OPENAI_API_KEY' } },
      models: {
        chat: { id: 'openai-chat-model-id' },
      },
    },
    anthropic: {
      adapter: 'anthropic-messages',
      options: { apiKey: { env: 'ANTHROPIC_API_KEY' } },
      models: {
        chat: { id: 'anthropic-chat-model-id' },
      },
    },
    deepseek: {
      adapter: 'openai-completions',
      options: {
        baseURL: 'https://api.example.com/v1',
        apiKey: { env: 'DEEPSEEK_API_KEY' },
      },
      models: {
        chat: { id: 'deepseek-chat-model-id' },
        reasoning: { id: 'deepseek-reasoning-model-id' },
      },
    },
  },
});
app.ts使用模型
import { createProvider } from '@alpha/provider';
import { config } from './provider.config.js';

const provider = createProvider(config);

const model = provider.use('deepseek', 'chat');
const reasoning = provider.use('deepseek', 'reasoning');
const another = provider.use('anthropic', 'chat');

const result = await model.generate({
  messages: [{ role: 'user', content: '你好' }],
  maxOutputTokens: 256,
});
console.log(result.text);

// 注入未来的 ADK；defineAgent 为示意 API。
const agent = defineAgent({ model, instructions: '你是一个助手。' });
所有模型 ID 和第三方 URL 都是占位符。示例中的 defineProviderConfig 提供类型提示；createProvider 负责运行时校验。Provider 使用 Alpha 自己的模型接口和 HTTP 适配器，运行时不依赖 AI SDK。
02

配置概念与参数

连接名称、适配器类型和上游模型 ID 各自独立。adapter 是 Alpha 的注册名，不会自动安装或执行同名 npm 包。

字段含义约定
providers.deepseek连接名称用户自定义、全局唯一；同一家服务可配置多条连接。
adapter选择具体适配器内置 anthropic-messages、openai-completions、openai-responses 和 openai-codex-responses；自定义名称需显式注册。
options.accessTokenCodex OAuth token 引用openai-codex-responses 必填，格式为 { env: 名称 }；应用负责获取和刷新。
options.baseURL服务 API 根地址可选；OpenAI 适配器默认 OpenAI 地址，第三方或本地端点需显式填写。地址不包含凭证。
options.apiKey认证配置{ env: 'NAME' } 引用服务端环境变量；openai-completions / openai-responses 可用 { none: true } 明确禁用认证。
options.headers静态请求头支持静态字符串或环境变量引用；generate 可提供单次请求头覆盖。认证及协议保留头不可覆盖。
options.queryParamsopenai-completions / openai-responses 查询参数可选的非敏感静态值；具体字段由适配器校验。
options.maxOutputTokensAnthropic 输出限制可选默认值；必须在配置或每次 generate 调用中提供。
models.chat.id模型 IDchat 是当前 Provider 内别名；id 是上游识别的模型名称。
本版建议模型条目统一使用 { id } 对象，暂不支持字符串简写。温度、输出 token 和工具定义通过 model.generate() 的请求参数传入。
03

四种内置适配器

openai-responses

Responses 协议，发送到 /responses；服务需要支持该协议。

openai-codex-responses

使用应用取得的 OAuth access token 调用公开 Responses API；登录与刷新由应用负责。当前不实现 ChatGPT 内部 Codex backend。

anthropic-messages

Anthropic 原生适配器；保留厂商协议和参数差异。

openai-completions

Completions 协议，发送到 /chat/completions；可接入支持该协议的第三方。

适配器名称区分实现而非模型厂商。比如第三方模型由兼容端点提供时，可以使用 openai-completions 或 openai-responses，具体取决于服务提供的协议；Anthropic 使用独立适配器。
04

第三方自定义适配器

兼容端点只需要静态配置；无法通过内置适配器连接的第三方服务，通过应用显式注册适配器。

custom-provider.ts扩展 API
import { createProvider, defineProviderConfig } from '@alpha/provider';
import { acmeAdapter } from '@example/acme-ai-adapter';

const config = defineProviderConfig({
  providers: {
    acme: {
      adapter: 'acme',
      options: { region: 'region-1', apiKeyEnv: 'ACME_API_KEY' },
      models: { chat: { id: 'model-id' } },
    },
  },
});

const provider = createProvider(config, {
  adapters: { acme: acmeAdapter },
});
const model = provider.use('acme', 'chat');

第三方包和字段是虚构示例。适配器负责校验其 options，并使用模型 ID 创建 Alpha 自己的 LanguageModel；其认证、配置与能力需单独定义。内置适配器使用类型约束；自定义 options 在运行时由适配器校验。

05

use 的运行时契约

接口 / 行为设计边界
createProvider(config, options?)同步校验配置、模型映射和 adapter 注册，保存配置快照。不读取密钥，不发送网络请求；非法配置立即报错。
provider.use(providerName, modelAlias)按名称与别名同步读取配置，在需要时读取环境变量并创建模型对象。不发模型请求；不确认服务在线、模型存在或密钥有效。返回 Alpha 自己的 LanguageModel，支持 generate()。
缓存与轮换首版不缓存模型对象；每次 use 都重新解析当前密钥并创建模型对象。已返回的模型对象保持原凭证快照；轮换后重新调用 use。动态认证和异步密钥另行设计。
provider.list()返回 Provider 名称、各模型别名和模型 ID。不读取密钥或联网，不返回认证信息、headers 和敏感 URL。
错误CONFIG_INVALID、PROVIDER_NOT_FOUND、MODEL_NOT_FOUND、SECRET_MISSING、ADAPTER_NOT_FOUND。错误包含安全的字段路径；模型调用的 HTTP 错误由 Provider 返回安全错误码和状态码，不隐式 fallback。
基于静态 TypeScript 配置，use 支持静态配置的 Provider 名称和对应模型别名补全；动态加载的配置依靠运行时校验。
06

社区参考与取舍

项目设计方式我们的取舍
OpenCode按 Provider 配置适配包、options 和 models。借鉴按连接组织模型；Alpha 使用注册名选择 adapter，保持静态配置简洁。
Vercel AI SDK通过厂商工厂及 registry 获取模型。仅作为社区设计参考；Alpha 的模型接口和 HTTP 适配器由我们实现。
LiteLLMGateway 配置以模型部署列表和路由为中心。我们是开发库，首版按 Provider 组织；不提前引入网关路由、负载均衡。
adapter 是 Alpha 基于调研作出的命名选择，不是社区统一标准。use 是我们选择的应用层 API，也不是对上述项目现有 API 的描述。
