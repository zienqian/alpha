01 / SCOPE

执行循环是微内核的核心

内核拥有 Agent 从输入到终态的完整执行闭环；模型、工具与业务策略通过插件或显式配置接入。微内核的边界按职责划分。

本轮定稿方向：Loop 内置在 core，由 createAgent 自动组装；ADK 的公开入口统一为 @alpha/adk/core。保留单 schema 工具和 Provider 直接接入。
范围微内核机制可扩展能力
推进内置 Loop、单 run、模型 → 工具 → 继续 / 结束模型实现、工具集合、上下文与授权策略
一致性历史唯一写入、消息配对、停止仲裁、预算与终态Session、数据库、摘要、持久化适配
接入轻量插件注册与生命周期、三个 hook、事件通知MCP、检索、UI、观测、业务依赖
工具定义createTool 标准 schema 归一化；受控校验与执行具体 schema 库由应用选择；业务 execute 可替换

实现必须保持的九条不变量

  1. 内核独占循环推进和正式历史写入；插件与观察者不持有控制句柄。
  2. 一个 Agent 最多一个 run，一个 run 最多一个已受理的模型或工具操作。
  3. 模型流正常结束且恰好一个 finish，才提交 assistant；text-delta 与 tool-call 通知均不触发执行。
  4. 工具只能来自本 run 已提交 assistant 的调用列表，按 assistantId 与 callId 配对。
  5. 参数校验、授权、执行依次发生；每次 await 后检查停止意图。
  6. 每个已确认调用恰好一个结果，每个 run 最多一个终态事件与结果。
  7. 内核不自动重试；当前 run 去重不等于外部恰好执行一次。
  8. 首次停止意图不可覆盖；终态等待所有已受理工作收束。
  9. 观察者故障不改变执行；必需策略走明确 hook。
02 / OWNERSHIP

一个公开入口，内核拥有 Loop

模块可以在内部拆分实现，对外统一提供 createAgent、createTool 和扩展契约。

应用
  createProvider(config).use(...) → LanguageModel
  createTool(...) / 静态 Plugin
                 ↓
@alpha/adk/core
  createAgent({ model, tools, plugins, instructions })
     ├─ 装配：收集贡献 → 校验冻结 → 启动插件
     └─ Agent.prompt(input)
           └─ 内置 Loop + Run controller
                ├─ Model gateway → LanguageModel.stream(...)
                ├─ Tool gateway  → Tool.prepare / execute
                ├─ History store
                └─ Event dispatcher
                      ↺ 还有工具请求则继续；终态统一收束

插件参与：beforeModel / authorizeTool / mapToolResult / observe
公开 API：不提供 loop 配置或 provideLoop，不暴露内部 LoopContext
包依赖：  ADK ── import type ──→ Provider 公开契约
外部能力：厂商 adapter / MCP / 存储 / 检索 / UI
Agent / Lifecycle

公开入口、插件注册与启动、运行互斥、快照、close；管理实例生命周期。

Loop / Run controller

内置推进循环、信号、预算、停止意图和唯一 finalizer；内核的控制中心。

Model gateway

直接调用 LanguageModel.stream；投影、流校验、结果提交。

Tool gateway

归属、prepare、授权、执行与去重账本；不开放旁路。

History store

进程内记录、配对验证、不可变快照与容量预留。

Event dispatcher

分配 seq、顺序通知、观察者异常隔离。

对象所有权与生命周期确定边界
Loop内核创建和调用；每个 run 独立运行状态默认串行推进是内核实现；不作为插件贡献，也不需要业务传入
Provider / LanguageModel应用或插件注入；Agent 生命周期内固定Provider 管协议与凭证；core 直接复用其公开模型契约
Plugin registrycore 内部；创建时临时注册，之后冻结只安装显式清单；无自动发现、下载、通用服务容器或热替换
Tool / createTool同一公开入口；创建时编译标准 schema 描述运行网关消费规范化 Tool；不依赖特定 schema 库
AgentState / Run recordAgent 持有跨轮历史；Run controller 持有单次状态信号、预算、操作锁与 completed 表不跨 run
continuation / responseId属于对应 assistant 的 Provider 原始结果原值保存；首版完整历史请求，不自动启用服务端增量续接
扩展性落实在能力与固定阶段：插件可以提供模型、增加工具、裁剪或补充上下文、授权和处理结果，并接入观测。模型 → 工具 → 再次模型的基本闭环由内核保证。图编排、多 Agent 与持久化执行可组合多个 Agent，首版不开放整段循环替换。

工程层面延续 K2 的 ADK → Provider 单向类型依赖提案；Provider 不反向依赖 ADK。实施时新增 @alpha/adk/core 子路径导出并同步 README / 边界检查；当前包尚未提供这些设计 API。

03 / CONTRACTS

统一从 @alpha/adk/core 使用

业务用法只需声明模型、工具、指令及可选插件；执行循环已经内置。以下均为设计附件，未写入 packages。

业务用法

import { z } from 'zod';
import { createAgent, createTool } from '@alpha/adk/core';
import { createProvider } from '@alpha/provider';
import { orders } from './app-deps.js'; // 应用提供业务依赖

// 模型目录与协议配置由 Provider 持有；use 创建实例，不发网络请求。
const provider = createProvider({
  providers: {
    primary: {
      adapter: 'openai-completions',
      options: { apiKey: { env: 'OPENAI_API_KEY' } },
      models: { chat: { id: 'your-model-id' } },
    },
  },
});

const getOrder = createTool({
  name: 'get_order',
  description: '查询订单状态',
  input: z.strictObject({ id: z.string().min(1).describe('订单号') }),
  effect: 'read', // 可省略，默认 unknown
  async execute({ id }, { signal }) {
    return JSON.stringify(await orders.get(id, { signal }));
  },
});
const agent = await createAgent({
  model: provider.use('primary', 'chat'), // Provider 直接接入
  instructions: '先查询事实，再回答。',
  tools: [getOrder],
});
try {
  const result = await agent.prompt('查询订单 A123');
  console.log(result.status, result.text);
} finally {
  await agent.close();
}

公开类型

// 拟议模块：@alpha/adk/core。声明附件，不是运行实现。
import type { LanguageModel, GenerateResult, Json as ProviderJson } from '@alpha/provider';
import type { StandardSchemaV1, StandardJSONSchemaV1 } from '@standard-schema/spec';

export type Awaitable<T> = T | Promise<T>;
export type Json = null | boolean | number | string | readonly Json[] | { readonly [k: string]: Json };
export type JsonObject = { readonly [k: string]: Json };
// 将递归 Provider JSON 固定映射为只读 JSON，避免类型无限展开。
export type DeepReadonly<T> = [T, ProviderJson] extends [ProviderJson, T]
  ? Json : T extends object
  ? { readonly [K in keyof T]: DeepReadonly<T[K]> } : T;
export type Effect = 'read' | 'write' | 'unknown';
export type Usage = Readonly<NonNullable<GenerateResult['usage']>>;
export interface AdkError { code: string; message: string }

// 复用 Provider 的结果结构；只增加历史身份及只读语义。
// text / finishReason / refusal / incompleteReason / responseId / continuation 原样保留。
export type AssistantMessage = DeepReadonly<GenerateResult> & {
  readonly id: string;
  readonly role: 'assistant';
};
export type ToolExecution = 'succeeded' | 'failed' | 'denied' |
  'not_executed' | 'outcome_unknown';
export interface ToolResultMessage {
  readonly id: string;
  readonly role: 'toolResult';
  readonly assistantId: string; // 与 callId 一起构成配对键
  readonly callId: string;
  readonly content: string;
  readonly execution: ToolExecution;
}
export type Message =
  | { readonly id: string; readonly role: 'user'; readonly content: string }
  | AssistantMessage
  | ToolResultMessage
  | { readonly id: string; readonly role: 'custom';
      readonly kind: string; readonly data: Json };

export interface ToolInfo {
  readonly name: string;
  readonly description: string;
  readonly inputSchema: JsonObject;
  readonly effect: Effect;
}
export interface RunContext<C> {
  readonly agentId: string;
  readonly runId: string;
  readonly signal: AbortSignal;
  readonly app: C;
}
export interface ToolContext<C> extends RunContext<C> {
  readonly assistantId: string; readonly callId: string;
}
// 规范化工具供适配器作者使用；业务侧只写 createTool({ input, execute })。
export interface PreparedTool<C> {
  readonly arguments: JsonObject;
  readonly execute: (ctx: ToolContext<C>) => Awaitable<string>;
}
export interface Tool<C = unknown> {
  readonly info: ToolInfo;
  readonly prepare: (
    raw: JsonObject, signal: AbortSignal
  ) => Awaitable<PreparedTool<C>>;
}
// prepare 校验一次；execute 闭包绑定同一份冻结参数。
// prepare 不做业务副作用；网关保证同一已确认调用只执行一次。

// 模型能力直接使用 @alpha/provider 的 LanguageModel。
// 没有 ADK 专属的请求、结果、流事件协议或第二层模型适配接口。
export interface ValidatedCall {
  readonly assistantId: string; readonly callId: string;
  readonly name: string;
  readonly arguments: JsonObject;
  readonly effect: Effect;
}
export interface HookMap<C> {
  beforeModel: (messages: readonly Message[], ctx: RunContext<C>) =>
    Awaitable<readonly Message[]>;
  authorizeTool: (call: ValidatedCall, ctx: RunContext<C>) =>
    Awaitable<{ action: 'allow' } | { action: 'deny'; reason: string }>;
  mapToolResult: (result: Readonly<ToolResultMessage>, ctx: RunContext<C>) =>
    Awaitable<string>;
}
export type Hooks<C> = {
  readonly [K in keyof HookMap<C>]?: readonly HookMap<C>[K][];
};
export interface Limits {
  maxModelCalls: number;        // 默认 8
  maxToolCalls: number;         // 默认 32；同时限制单响应调用列表长度
  timeoutMs?: number;           // 缺省无墙钟期限；不代表强制终止
  maxModelOutputBytes: number;  // 默认 1 MiB
  maxToolResultBytes: number;   // 默认 128 KiB
  maxHistoryBytes: number;      // 默认 4 MiB
  maxHistoryMessages: number;   // 默认 512
}
export type RunStatus = 'completed' | 'refused' | 'incomplete' | 'unknown' |
  'limited' | 'cancelled' | 'failed';
export type RunResult = {
  readonly runId: string;
  readonly text: string; // 本 run 最后已提交的 assistant 内容，可能为空
  readonly usage?: Readonly<Usage>; // 仅汇总已报告量，不是完整费用账单
} & (
  | { readonly status: 'failed'; readonly error: AdkError }
  | { readonly status: Exclude<RunStatus, 'failed'>; readonly reason?: string }
);
export interface AgentState {
  readonly status: 'idle' | 'running' | 'cancelling' | 'closed';
  readonly historyStatus: 'ready' | 'blocked';
  readonly messages: readonly Message[];
}
export interface EventMeta {
  readonly agentId: string; readonly runId: string; readonly seq: number;
}
export type AgentEvent = EventMeta & (
  | { type: 'run.start' }
  | { type: 'run.stop_requested'; status: 'cancelled' | 'failed' | 'limited' }
  | { type: 'model.start'; modelCallId: string }
  | { type: 'model.delta'; modelCallId: string; text: string }
  | { type: 'model.end'; modelCallId: string;
      outcome: GenerateResult['outcome'] | 'failed' | 'cancelled' }
  | { type: 'tool.start'; assistantId: string; callId: string; name: string }
  | { type: 'tool.end'; assistantId: string; callId: string; execution: ToolExecution }
  | { type: 'message.commit'; messageId: string; role: Message['role'] }
  | { type: 'run.end'; status: RunStatus }
);
export type AppOption<C> = undefined extends C
  ? { appContext?: C } : { appContext: C };
export type AgentOptions<C = undefined> = AppOption<C> & {
  id?: string;
  instructions: string;
  model?: LanguageModel; // 直接传 provider.use(...)，或由插件贡献
  plugins?: readonly Plugin<NoInfer<C>>[];
  signal?: AbortSignal; // 只取消创建 / 插件启动，不绑定后续 run
  tools?: readonly Tool<NoInfer<C>>[];
  hooks?: Hooks<NoInfer<C>>;
  limits?: Partial<Limits>;
  onObserverError?: (error: AdkError) => void;
};
export interface Agent<C = undefined> {
  readonly id: string;
  readonly state: AgentState;
  prompt(input: string, options?: { signal?: AbortSignal }): Promise<RunResult>;
  subscribe(listener: (event: AgentEvent) => void): () => void;
  abort(reason?: string): void;
  waitForIdle(): Promise<void>;
  replaceMessages(messages: readonly Message[]): void;
  close(): Promise<void>;
}
export declare function createAgent<C = undefined>(
  options: AgentOptions<C>
): Promise<Agent<C>>; // 插件就绪后才返回可用实例；无插件也保持同一签名

// 以下声明同属 @alpha/adk/core；没有另一套创建入口。
type InputSchema = StandardSchemaV1 & StandardJSONSchemaV1;
type Infer<S extends InputSchema> = DeepReadonly<StandardSchemaV1.InferOutput<S>>;

export declare function createTool<S extends InputSchema, C = unknown>(spec: {
  name: string;
  description: string;
  input: S;
  effect?: Effect;
  execute(input: Infer<S>, ctx: ToolContext<C>): Awaitable<string>;
}): Tool<C>;
// 单 schema：类型推导、校验与 JSON Schema 描述由同一 input 提供。
// core 只使用标准结构协议，不引入 Zod 或其他 schema 库的运行时依赖。

export interface PluginAPI<C> {
  provideModel(model: LanguageModel): void;
  addTool(tool: Tool<C>): void;
  hook<K extends keyof HookMap<C>>(name: K, fn: HookMap<C>[K]): void;
  observe(listener: (event: AgentEvent) => void): void;
}
export interface Plugin<C = undefined> {
  readonly id: string;
  readonly apiVersion: 1;
  readonly requires?: readonly string[];
  setup(api: PluginAPI<C>): void;
  start?(signal: AbortSignal): Promise<void>;
  dispose?(): Awaitable<void>;
}
// setup 仅声明贡献；注册 API 在 setup 返回后关闭。
// createAgent 收集贡献后要求恰好一个 model，拒绝重复工具和非法配置。
// 插件不接收 loop、callModel、callTool 或可写历史引用。

插件定义

import type { Plugin } from '@alpha/adk/core';

type App = { allowWrite: boolean };

// 静态定义：没有仅返回原对象的 createPlugin 包装。
export const access = {
  id: 'access',
  apiVersion: 1,
  setup(api) {
    api.hook('authorizeTool', (call, { app }) => {
      if (call.effect !== 'read' && !app.allowWrite) {
        return { action: 'deny', reason: '当前上下文不允许写操作' };
      }
      return { action: 'allow' };
    });
  },
} satisfies Plugin<App>;

内置 Loop

// 私有实现草图：core/internal/create-loop.ts。
// 不从 @alpha/adk/core 导出，不要求调用者创建或注入。
import type {
  RunContext, AssistantMessage, ToolResultMessage,
} from '@alpha/adk/core';

interface LoopContext<C> extends RunContext<C> {
  callModel(): Promise<AssistantMessage>;
  callTool(assistantId: string, callId: string): Promise<ToolResultMessage>;
}

function createLoop<C>() {
  return {
    async execute(ctx: LoopContext<C>): Promise<AssistantMessage> {
      while (true) {
        const reply = await ctx.callModel();
        if (reply.outcome !== 'tool_calls') return reply;

        for (const call of reply.toolCalls) {
          await ctx.callTool(reply.id, call.id);
        }
      }
    },
  };
}
// 内部网关检查停止意图与预算；不允许继续时抛出内部停止信号。
// Loop 不吞掉停止信号；Run controller 统一映射终态并完成 finalizer。
// 每个调用都 await；工具批次串行；未配对完成不能进入下一次模型调用。
// 本代码仅呈现推进算法，不是已实现或可独立运行的框架。
公开工厂：ADK 只有 createAgent、createTool 从 @alpha/adk/core 导出；Provider 的 createProvider 保持在其模块。静态插件用对象 + satisfies Plugin；有配置或资源的插件使用 createXPlugin。createLoop 是私有实现工厂。

统一采用 await createAgent(...)：插件启动成功后才返回可用 Agent；无插件时也保持相同 Promise 签名。createTool 同步归一化 schema，不进行网络 I/O。公开类型、业务示例、静态插件与内部循环草图已通过 TypeScript strict 检查，覆盖 Provider 直接注入、单 schema 推导、异步创建和内部循环边界；运行机制仍待实现。

04 / STATE MACHINE

Agent 状态与 Run 结果分开

Agent.status 表示实例能否接收工作；RunResult.status 表示某次执行结果；historyStatus 单独表示能否安全续接。

动作与条件转换确定行为
await createAgent(options)初始化 → idle / ready注册、校验、冻结、启动插件后返回 Agent；失败 reject，清理已启动资源
prompt，idle + readyidle → running首个 await 前占用 run；登记 signal，发 run.start，提交 user，再启动内置 Loop
prompt 输入非法 / busy / closed / blocked状态不变返回 rejected Promise；无 run、事件或历史变更
prompt 的 signal 已 abortedidle → running → idle生成 cancelled run 与 start/end；不提交 user，不启动内置 Loop
abort / timeout / 执行故障 / 达限制running → cancelling记录停止意图并 abort 内部信号；不提前释放 Agent
收束完成running / cancelling → idle补齐配对、生成终态、发 run.end 后 settle prompt
close()先收束 run，再释放插件，最后完成 close立即置内部 closing 闸门，拒绝新 prompt；复用同一关闭 Promise；插件 dispose 失败也继续清理并聚合错误
replaceMessages仅 idle 且非 closing整体验证后原子替换；拒绝孤立结果和 outcome_unknown；不调用模型或工具
waitForIdle不改变状态只等待当前 run 的 finalizer；插件释放完成须等待 close

cancelling 表示正在停止和清理，最终结果也可能是 failed / limited。closing 是内部闸门；初始化阶段不暴露 Agent。run 收束后可置 closed 拒绝操作，但 close 的 Promise 还须等待插件资源释放。

    05 / MODEL GATEWAY

    callModel：直接消费 Provider 的统一接口

    不再要求应用写模型桥接。内核中的 Model gateway 是私有执行机制，使用现有 GenerateInput / GenerateResult / StreamEvent；不增加公共模型协议。

    阶段处理必须满足
    M1 受理检查 run 有效、无停止意图、无 activeOp、无 pending工具结果不完整时不能继续模型调用
    M2 投影取历史快照，按顺序 await beforeModel投影不修改历史；每次 await 后重检停止
    M3 转换验证投影与配对，转为 Provider Message[] / ToolDefinition[]仅在内核内部做记录到请求的转换；不解析厂商协议
    M4 预算原子预留 modelCalls，生成 modelCallId，发 model.start计数表示 LanguageModel.stream 调用尝试；立即失败也不退还
    M5 消费text-delta 仅通知；tool-call 不执行；finish.result 暂存finish 后再有事件即协议错误；必须继续等迭代正常结束
    M6 结果验证恰好一个 finish、合法 outcome、完整且唯一的工具调用列表tool_calls 非空；其他 outcome 无工具；以 finish.result.toolCalls 为唯一执行来源
    M7 提交检查容量、复制冻结完整 GenerateResult，再补 id / role保留 text / finishReason / refusal / incompleteReason / responseId / continuation；无 await 原子提交

    历史到 Provider 请求：一处内部投影

    ADK 正式记录 / 配置Provider 字段处理规则
    instructions首条 system 消息每次调用显式携带；beforeModel 处理历史，不改 Agent instructions
    user.contentuser.content复制字符串
    assistant 的 GenerateResultassistant.content = text；toolCalls；continuation结果元数据留在历史；只复制 Provider Message 支持的字段
    toolResulttool.toolCallId = callId；contentexecution 与 assistantId 仅为内核事实；按所属批次保持结果顺序
    custom无默认转换必须由 beforeModel 显式转换成可发送消息或移出本次投影；未处理则失败
    Tool.infoToolDefinition：name / description / inputSchemaeffect 与 execute 不发给模型；schema 为创建时缓存的规范化结果
    run.signalGenerateInput.signal直接透传；应用及插件创建的模型实现须响应取消

    发出请求使用新建的 Provider 消息数组与 JSON 数据，不把冻结历史对象作为可变输入传出。保留的工具批次必须完整且与正式记录一致；允许整组裁剪。带 continuation 的 assistant 及其工具声明不可被 hook 改写。

    Provider 流事件的唯一处理规则
    • text-delta → model.delta，只是 UI 预览。
    • tool-call 是 Provider 的通知事件；内核不据此提交 pending 或执行工具，也不累计成另一套调用列表。
    • finish.result 正常收束后，原样保存为 assistant 的结果字段；只从其中的 toolCalls 生成 pending。
    • 缺失 / 重复 finish、finish 后事件、流异常或坏批次：不提交本次 assistant，不执行工具。
    • refused / incomplete / unknown 是合法结果；内置 Loop 将相应 outcome 作为终态，不执行工具。RunResult.reason 优先取 refusal / incompleteReason，否则取 finishReason。
    • 流期间取消则不提交本次 assistant；迟来的完整结果不覆盖停止意图。收到 finish 但流不结束，仍需等待协作取消。
    续接边界：首版采用完整历史请求

    保留 GenerateResult.continuation 的原始结构和值，复制冻结后跟随对应 assistant 回传。当前 Provider 类型为 AnthropicContinuation；协议块的解释仍由 Provider 完成，不再包装 owner / data。Agent 生命周期内 model 固定；跨模型导入历史不保证续接兼容，外层 codec 必须绑定来源 model.provider / modelId，不能直接迁移 opaque 数据。

    首版每次发送经 beforeModel 投影后的完整上下文，previousResponseId 不设置。responseId 保留供审计与后续扩展使用，不能因为字段存在就自动启用服务端会话。未来若增加增量续接，需单独设计游标与重放语义，避免重复发送全部历史。

    模型参数与职责

    首版 callModel() 不接受另一套泛型 ModelRequest；模型选择与固定参数由 Provider / 注入的 LanguageModel 管理。内核只组装 messages、tools、signal。若增加每 run 的 temperature / thinkingLevel 等可调项，应直接引用 Provider 字段并单独评审。

    内核不调用厂商 SDK，也不做自动重试或 fallback。modelCalls 只统计内核受理的调用，不统计 hook 自行发出的 HTTP；模型方法按对象调用，保留其 this 接收者。

    06 / TOOL GATEWAY

    callTool：校验、授权、执行共用一条路径

    调用键为当前 run 内的 (assistantId, callId)。不同模型响应可以复用供应商 callId，同一响应内不允许重复。

    阶段操作失败语义
    T1 归属与去重已完成同键直接返回既有结果；否则要求无 activeOp，且该调用属于当前 pending错误消息、旧 run、伪造 ID：CALL_NOT_PENDING；并发新操作：RUN_OPERATION_BUSY
    T2 prepare查冻结工具表，await prepare(raw, signal)；验证规范化参数为 JSON 对象未知工具或校验失败：not_executed，run failed，副作用 0
    T3 授权按顺序 await authorizeTool，参数冻结且与 execute 绑定一致首个 deny 提交 denied；抛错 failed；不执行工具
    T4 执行重检停止、原子预留工具预算、发 tool.start；通知后再查停止，再进入 execute观察者在 tool.start 中 abort 时仍不执行；已预留计数不退还
    T5 内容处理await execute 返回字符串；检查类型 / 大小，再依次 mapToolResult正常返回后执行事实已确认；内容处理失败不重试
    T6 提交唯一结果写入历史，删除 pending，加入 completed；发 message.commit → tool.end停止意图存在则由 finalizer 继续收束，Loop 不启动新调用
    发生位置 / 情况executionRun / 历史
    参数无效、工具不存在、execute 前取消not_executedfailed / cancelled；配对补齐后 ready
    授权 denydenied默认可继续模型解释；ready
    execute 返回成功succeeded可继续；ready
    read 工具进入 execute 后抛错failedrun failed；信任 read 声明，ready
    write / unknown 工具进入 execute 后抛错（含取消）outcome_unknown按首次停止意图 failed / cancelled；blocked
    工具已返回，但 mapToolResult / 输出检查失败succeeded + 安全占位内容run failed；已知执行完成，ready，不重跑
    取消后工具仍正常返回succeeded记录确认结果；终态仍 cancelled
    effect 是受信任声明，不是安全证明。默认 unknown，异常时保守阻断续接。执行事实仅由 execution 表达，不再维护重复的 isError。普通工具返回文本，抛错按上表收束。
    prepare 为何不让开发者多写一套接口

    业务仍只写 createTool({ input: schema, execute })。core 的 createTool 工厂编译 schema 描述，并生成 prepare：校验一次，把同一份复制冻结后的 JSON 参数交给授权和执行闭包。内核不会在授权后重新解析成另一份参数。

    prepare 不产生业务副作用。无 app 依赖的工具默认 C=unknown，可用于不同 Agent；需要依赖时只标注 ToolContext<App>。规范化 Tool 是可信适配器的公开契约，不是防恶意进程内代码的安全边界。

    07 / EXTENSIONS

    插件扩展能力，内核控制推进

    注册仅发生在 createAgent 的装配阶段；运行时只执行冻结后的贡献。

    扩展点可做什么顺序与失败
    provideModel / addTool声明模型与工具能力；与直接配置汇总恰好一个 model；工具名唯一；冲突创建失败
    beforeModel生成本次上下文投影；保留的工具批次与 continuation 不可改写按注册顺序变换，统一验证；抛错 failed
    authorizeTool对已校验参数 allow / deny，不改名或参数首个 deny 短路；抛错 failed；拒绝不执行工具
    mapToolResult仅变换返回文本，不改执行事实或归属逐项 await；失败保留工具事实并终止
    subscribe / observe消费只读事实事件观察者异常隔离；没有持久化或事务承诺
    start / dispose连接与释放插件资源实例生命周期内各一次；失败逆序清理

    插件不获取 callModel / callTool、循环执行器或可写历史。三个 hook 固定在内核网关阶段，不提供可重复调用 next 的通用中间件。直接配置 hooks 在前，插件按清单顺序追加；业务能力不会绕开内核的一致性规则。

    配置冻结与重入

    创建时复制冻结工具描述、工具表、hook 数组与 limits；函数和 appContext 按引用持有，不冻结用户客户端。运行中不变更模型、工具、插件或 hooks；换配置创建新 Agent。

    事件回调分发期间，prompt / replaceMessages / close 等状态修改操作报告 REENTRANT_MUTATION；abort 允许请求取消。subscribe / unsubscribe 使用本次分发开始时的列表快照，变化只影响后续事件。新请求可放到回调退出后的微任务。

    08 / TERMINATION

    内置 Loop 与统一收束

    stopIntent 只能首次写入 cancelled / failed / limited；后来原因不覆盖。所有内部网关错误与停止信号向同一个 Run controller 汇合。

    触发结果内核行为
    模型 outcome 为 completed / refused / incomplete / unknown对应自然终态Loop 返回最后已提交 assistant；要求无 activeOp、无 pending、无停止意图
    模型 outcome 为 tool_calls继续本 run按列表顺序等待全部工具结果；配对完整后才再次调用模型
    abort / 外部 signal / timeout / closecancelled记录来源，禁止新调用；等待受理中的工作收束
    模型 / 工具 / 历史预算耗尽limited内部网关抛停止信号，Loop 退出；finalizer 补未执行结果
    模型、工具、hook 或协议故障failed稳定错误码；保留已确认事实；不自动重试
    内部 Loop 提前返回或存在未等待操作failed / INTERNAL_INVARIANT作为内核缺陷处理；abort 并等待活动操作，不释放后台任务

    统一 finalizer：六步

    1. 关闭 run 操作入口，等待内置 Loop、已受理操作和已开始的结果处理返回。
    2. 为未开始的 pending 补 not_executed；未知执行补 outcome_unknown；已提交结果不重复产生。
    3. 出现 outcome_unknown 即 historyStatus=blocked；已知成功结果保留 succeeded。
    4. 生成 RunResult，准备唯一 run.end；关闭路径禁止接收新 run。
    5. 在重入保护内分发 run.end，再释放占用并 settle prompt / waitForIdle；正常路径恢复 idle，关闭路径置 closed 后进入插件清理。
    6. 移除 timer、外部 signal listener、临时文本缓冲、completed 表与 run 引用；close 另行等待所有 dispose 完成。
    协作取消：内置 Loop 在每个受控步骤检查停止；如果模型、工具或 hook 不响应 signal，prompt 和 close 仍需等待该工作返回。timeoutMs 是请求取消的时限，硬终止由进程隔离层提供。
    内部并发不变量

    Loop 按顺序 await 每次模型与工具操作；插件没有执行网关入口。activeOp 仍用于内核防御与故障注入测试：若实现错误造成重叠操作，记录 RUN_OPERATION_BUSY 并等待已有操作收束。

    异常、预算与用户取消按控制器接收顺序仲裁。即使 run.cancelled，工具随后确认成功也记录 tool.succeeded；停止意图不能抹去已发生的事实。

    09 / EVENTS

    事件是事实通知，正式状态只有一个来源

    run.start
message.commit(user)
model.start → model.delta* → message.commit(assistant) → model.end
  tool.start → message.commit(toolResult) → tool.end
model.start → model.delta* → message.commit(assistant) → model.end
run.end(completed)

授权拒绝 / 执行前校验失败：message.commit(toolResult) → tool.end
通常没有 tool.start；若在 tool.start 回调中被取消，end=not_executed。
    关注点契约
    排序seq 从 1 开始，run 内递增；不同 Agent 无全局顺序。先提交再通知，读 state 可见该记录
    无订阅者没有队列，也不等消费者；执行一致
    慢监听同步阻塞会拖慢调用栈；回调不得阻塞 I/O，异步 exporter 自管有界队列
    监听失败同步抛错 / 异步拒绝交 onObserverError；不等待；错误处理器再抛错不递归报告
    正文model.delta 主动携带 UI 文本；其他事件仅 ID / 状态，message.commit 不附全文或 continuation
    持久化事件无重放 / 事务承诺；可靠保存与审计须显式 await，不能依赖普通观察者
    背压首版不提供无限 AsyncIterable 队列；应用可写独立有界适配
    10 / DATA & LIMITS

    完整历史、不可变快照与资源边界

    数据规则
    消息 ID内核生成正式消息 ID；导入历史全局唯一；custom ID 同样检查
    配对toolResult.assistantId + callId 匹配唯一声明，结果在所属 assistant 之后；禁止孤立或重复结果
    自定义消息kind 使用命名空间，data 为 JSON；beforeModel 显式转成可发送消息或移出投影，未处理则拒绝
    continuation直接复用 GenerateResult.continuation；复制冻结、绑定原 assistant；Provider 解释协议，不新增 owner / data
    快照每次提交新顶层数组与新记录；旧快照共享不可变消息；delta 不触发全历史复制
    blocked 恢复replaceMessages 拒绝 outcome_unknown；应用先核对外部系统，再提供配对完整、结果已确认的历史
    持久化codec 外置，需保存 historyStatus / 格式版本 / continuation；普通 JSON 序列化不等于可恢复执行

    以下默认值是待评审建议，不是性能实测

    限制默认值触发行为
    maxModelCalls8 / run调用 LanguageModel.stream 前预留；超出 limited
    maxToolCalls32 / run执行阶段前预留；同一模型响应调用列表长度也不得超过该值
    timeoutMs不设置配置后从 run 受理开始计时；取消后仍等待协作
    maxModelOutputBytes1 MiB限制 delta 总字节与最终结果 JSON 字节；超出 failed，不提交 assistant
    maxToolResultBytes128 KiB限制原始返回及每次变换；已执行则保留 succeeded 占位并 failed
    maxHistoryBytes / maxHistoryMessages4 MiB / 512 条UTF-8 JSON 字节，包含 continuation；提交前检查，容量不足 limited，不自动裁剪
    工具结果的容量必须提前预留

    提交带工具调用的 assistant 前，为每个工具结果预留消息条数与安全占位记录空间。放不下就不提交 assistant、不执行任何工具。预留按真实 ID / callId 与固定占位内容序列化计算。

    正常结果超过可用历史空间时，使用预留写入短占位内容并保留 execution，终止 run；不能丢失已发生的副作用。输出过大归 failed，历史容量不足归 limited，以最先检测到的停止意图为准。run 结束释放未用预留。

    11 / PLUGINS

    插件装配也是 core 的内部机制

    公开入口统一；轻量注册与生命周期在内部独立实现。第三方能力的实现仍留在插件模块。

    阶段core 的确定行为插件责任
    预检查验证 options、signal、插件 ID / apiVersion / requires；依赖需在清单前面显式提供插件清单；无自动发现或下载
    setup同步向临时注册表收集贡献；调用结束即撤销注册能力只声明 model、tool、hook、observer；不分配需要释放的外部资源
    校验 / 冻结合并直接配置与插件贡献；恰好一个 model，工具名唯一；创建内置 Loop不能贡献或替换 Loop；不能在 start 后继续注册
    start按清单顺序 await；缺省视为立即成功；全部完成才返回 Agent在此建立连接；响应初始化 signal
    创建失败 / 取消abort 启动信号；等待当前启动返回后，逆序 dispose 已进入启动阶段的插件，包含失败者每个 dispose 至多调用一次；未进入启动阶段的插件不处理
    close立即禁止新 run → 等待 Loop 收束 → 逆序 dispose → settle close一个 dispose 失败不阻断其他清理；资源由所属插件释放

    初始化 signal 只用于创建阶段，成功后移除关联监听，不成为后续 run 的取消源。所有 start / dispose 均须合作返回；创建失败的主因保留，清理失败作为聚合附加信息。

    保留轻量性：core 只认识插件生命周期和固定贡献类型，不包含 MCP 客户端、数据库驱动、厂商 SDK 或 UI。createTool 使用 Standard Schema / Standard JSON Schema 的结构协议，schema 库由应用传入。

    直接 model 与 provideModel 重复时创建失败；二者都未提供时同样失败。图编排、checkpoint、暂停审批、热重载和不可信插件隔离后置，不扩张首版 Loop。

    createAgent 只有异步版本；createTool 为同步工厂。

    分类示例出口

    模型协议MODEL_PROTOCOL / MODEL_TOOL_BATCH_TOO_LARGERunResult failed；不提交坏 assistant
