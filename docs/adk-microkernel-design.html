以小内核承载稳定机制，以可替换执行器承载运行策略，让模型、工具、状态与编排能力能够独立演进。

ALPHA ADK设计讨论稿TYPESCRIPT / NODE.JS
本方案的核心判断微内核的重点是清晰的依赖与扩展边界。默认体验应足够简单，同时允许开发者替换执行策略。本文为目标设计，不代表功能已实现。
01 / Principles

先约束边界，再扩展能力

框架提供可靠的运行机制，应用决定使用哪些能力。保持少量稳定原语，同时为不同执行方式留下空间。

01

内核只保留机制

运行生命周期、基础契约、取消、事件和扩展组装构成基础。图、MCP、持久化和平台集成按需加入。

02

策略可以替换

默认提供工具循环；自定义执行器可以使用相同的模型、工具与运行边界，表达其他工作方式。

03

默认可观察、可控制

每次运行拥有独立身份、事件和预算。权限由应用及策略决定，工具副作用前完成校验和授权。

03 / Contracts

把职责放到正确的位置

Agent 描述能力，Executor 决定执行方式，Runtime 管理生命周期。三者分离是复用与替换的基础。

对象职责边界
Agent声明指令、模型、工具及默认配置可复用定义；不绑定某种图或编排框架
Runtime / Run组装依赖并管理一次执行的生命周期Run 拥有独立 ID、取消信号、事件与结果
Executor实现工具循环、工作流或自定义运行算法通过公开边界使用模型、工具和事件
Tool提供名称、描述、输入 schema 和执行函数先校验与授权；默认不自动重试
Session / Checkpoint分别保存跨轮会话和未完成执行的恢复状态两个不同问题；首版不承诺崩溃恢复
Policy / Observer前者影响执行，后者提供日志、指标与 trace安全策略失败应阻止操作；观察者默认不改变运行结果
04 / Extension model

扩展点少而明确

用接口替换实现，用中间件包装操作，用观察者记录事实；避免让插件任意修改内部状态。

REPLACE

接口替换

模型、执行器和 session store 等有明确契约；一次运行明确选择实现。

INTERCEPT

有顺序的中间件

模型或工具调用前后执行策略；顺序、失败语义和 next 调用次数均需规定。

OBSERVE

只观察的订阅者

日志、指标和 trace 默认不影响主流程；默认不采集模型正文或工具参数。

ADAPT

外部能力适配

MCP、存储和观测平台通过公开契约接入。进程内插件与应用共享权限，并非安全沙箱。

05 / Runtime

默认循环清晰，状态边界明确

简单场景开箱即用；复杂场景可以换执行器。每次模型结果先判断终态，再决定是否执行工具。

RUN STATE

当前运行

保存本次执行状态、计数和取消信号。事件在单个 run 内按序发送，不承诺跨 run 的全局顺序。

SESSION

跨轮会话

保存对话历史。ContextBuilder 决定本次实际发给模型的内容；存储历史不等于全部进入上下文。

CHECKPOINT

执行恢复

未来单独设计版本、并发与副作用对账。持久化本身不能保证外部操作恰好执行一次。

Provider 续接：保留 Anthropic continuation 与 Responses previousResponseId 的不同语义；续接数据可能敏感且绑定模型，不能静默丢失或跨模型复用。
06 / Research

从社区吸收，而非照搬

不同项目解决了不同层次的问题。Alpha 保持少量原语，以可选扩展组合这些能力。

项目借鉴Alpha 的选择
OpenAI Agents SDK精简原语、工具、handoff 与 trace学习易用性；保留替换执行器的能力
Google ADKAgent、Runner、Session 的职责分离借鉴概念边界；按需引入外围能力
LangGraph显式状态、检查点、工作流与中断图作为可选执行方式；恢复语义独立设计
AutoGen Core消息驱动和多 Agent 系统保留消息边界；首版不引入分布式运行时
07 / Roadmap

从可验证的最小内核出发

每个阶段以可观察的结果退出，而不是以模块数量衡量完成度。

P0

契约验证

确认真实场景；验证 Provider 类型兼容、流式终态与续接。

P1

可运行内核

实现默认工具循环、事件、取消、预算及 schema 校验。

P2

扩展能力

中间件、观察者、内存 session 和自定义执行器示例。

P3

真实接入

接入目标模型服务；验证文本、工具、流和续接。

P4

按需演进

以真实用例推动 MCP、多 Agent、审批或持久执行。

关键验收：同一个 Agent 可切换模型；同一组工具可用于不同执行器；替换 session 和观测实现时无需修改 Agent。
